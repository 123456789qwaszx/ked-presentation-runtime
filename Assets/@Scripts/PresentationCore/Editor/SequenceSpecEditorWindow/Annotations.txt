// =================================================================================================
// SequenceSpecEditorWindow — Integrated Comment Guide (English)
//
// Purpose
// - This file is a “one-stop structural guide” for the Unity EditorWindow that edits SequenceSpecSO
//   (Nodes / Steps / Tracks / Commands).
// - Even if the actual implementation is split across multiple partial files, reading this comment
//   should restore the full mental model:
//   “who owns what / where to change what / which parts depend on which.”
//
// Big Picture (Data Model the editor edits)
// - SequenceSpecSO
//   - sequenceKey
//   - nodes : List<NodeSpec>
//     - NodeSpec.editorName
//     - NodeSpec.steps : List<StepSpec>
//       - StepSpec.editorName
//       - StepSpec.gate : GateToken
//       - StepSpec.tracks : StepTracks
//         - interaction/setup/motion/dialogue/fx : List<CommandSpecBase> (SerializeReference)
//       - StepSpec.compiled : List<CommandSpecBase> (runtime order preview, SerializeReference)
//
// UI / UX Layout (Editor Window)
// - Top: Toolbar (target picker, search, Ping, shortcuts popup)
// - Header: sequenceKey, Auto-fill(Role), Gate Defaults, RoleKey slots, warnings
// - Left: Nodes list (+ multi-delete UI)
// - Right: Steps list + Step details + Commands + Compiled Preview + bottom Command Bar
//
// Shared Design Principles
// - To handle SerializeReference (ManagedReference) command lists robustly:
//   - ReorderableList uses propertyPath caching; invalidate (set to null) when needed to rebuild safely.
//   - Foldout (expanded/collapsed) state is NOT trusted to SerializedProperty.isExpanded; stored separately.
// - Prefer wrapping data mutations with DelayModify() to avoid GUI event conflicts.
// - Keep a consistent “Undo -> Dirty -> Apply -> Compile -> Repaint” pipeline.
//
// -------------------------------------------------------------------------------------------------
// [0] Main Window (Authority) — Lifecycle / Binding / Global Policies
//
// Responsibilities (the “owner” level)
// - EditorWindow lifecycle: OnEnable / OnDisable / OnGUI / OnSelectionChange
// - targetSequence (SequenceSpecSO) binding: _so, _sequenceKeyProp, _nodesProp
// - Global UI state:
//   - Selection / navigation: _navColumn, _selectedNode, _selectedStep, _activeTrack
//   - List caches: _nodesList / _stepsList / _commandsList, _stepsPropPath / _commandsPropPath
//   - Scroll / jump: _nodesScroll / _rightScroll / _compiledScroll, _scrollToNewCommand, etc.
// - Global input routing (keyboard navigation / delete shortcuts)
// - “Recompile on changes” policy decision (ApplyModifiedProperties -> ForceCompileAll)
//
// Good places to modify here
// - Initialization order (LoadPreferences / LoadFoldouts / RebuildIfNeeded call order)
// - Rebuild strength when targetSequence changes (force) + cache invalidation scope
// - ApplyModifiedProperties -> SetDirty / Compile policy (conditional compile, debouncing, etc.)
// - Track system contract (TrackTabs / TrackFieldNames / TrackTypes)
//
// -------------------------------------------------------------------------------------------------
// [1] Layout / Drawing (Toolbar / Header / Panels) — “UI composition only”
//
// Responsibilities
// - DrawToolbar()
//   - Target SequenceSpecSO picker (ObjectField) -> RebuildIfNeeded(force:true) + LoadFoldouts()
//   - Search field (_searchField)
//   - Ping button (ping the asset)
//   - Shortcuts popup (ShortcutsPopup)
//
// - DrawHeader()
//   - sequenceKey edit/display
//   - Auto-fill(Role) toggle (stored in EditorPrefs)
//   - Placement for Gate Defaults bar + RoleKey slots bar
//   - Warnings: empty sequenceKey, no nodes, etc.
//
// - DrawNodesPanel()
//   - Nodes list (scroll + ReorderableList)
//   - Add Node button
//   - Multi-delete UI (Delete / Esc / checked count)
//
// - DrawRightPanel() / DrawNodeEditor()
//   - Steps list for selected node + Step shortcuts
//   - Selected Step detail (gate / track tabs / commands)
//   - Compiled Preview + bottom Command Bar (+Command, node-level Expand/Collapse All)
//
// Good places to modify here
// - Overall layout (column widths, spacing, scroll areas)
// - Header control alignment/placement (gate/role widgets)
// - Buttons and micro-UX (+Node/+Step/+Command, multi-delete UI)
// - Bottom bar scope UI (node-level Expand/Collapse All)
//
// Note
// - This section should “draw + call into utilities.”
//   Keep actual data edits delegated to DelayModify/CRUD helpers to avoid instability.
//
// -------------------------------------------------------------------------------------------------
// [2] ReorderableList Build & Lifetime — Nodes/Steps/Commands binding & caching
//
// Responsibilities
// - RebuildIfNeeded(force)
//   - Recreate _so / _sequenceKeyProp / _nodesProp
//   - Preserve/clamp selection indices
//   - Invalidate propPath caches (_stepsPropPath / _commandsPropPath)
//   - Invalidate list caches (_nodesList / _stepsList / _commandsList)
//   - Coordinate with foldout cache init/reset policy when structure changes
//
// - BuildNodesList()
//   - Build left Nodes ReorderableList
//   - Multi-delete checkbox mode (_deleteMultiMode / _checkedNodes)
//   - Search dimming (NodeMatchesSearch)
//   - On node selection change, invalidate Steps/Commands caches so right panel updates correctly
//
// - EnsureStepsList(nodeProp, stepsProp)
//   - Build/cache Steps ReorderableList for current node
//   - Step summary (editorName, gate summary, compiled count, etc.)
//   - Dragging flag (_isDraggingSteps) management
//   - Context menus + reorder callbacks (Dirty/Compile/Repaint pipeline)
//
// - NodeMatchesSearch()
//   - Determine “matches” by scanning step/compiled/command summaries for the search text
//
// Good places to modify here
// - Nodes/Steps labels & summary formats
// - Search/filter UX and dimming policy
// - Context menu insertion policy (add/duplicate/delete location)
// - Rebuild conditions and cache invalidation scope (“when to rebuild”)
//
// -------------------------------------------------------------------------------------------------
// [3] Step Detail (Right Panel) + Compiled Preview — “Step editing owner”
//
// Responsibilities
// - Render selected Step (StepSpec) details:
//   - Step Label (editorName)
//   - GateToken UI + Default Gate preset dropdown integration
//   - Track tabs (Interaction/Setup/Motion/Dialogue/FX)
//   - Commands list for the selected track + shortcut handling
//
// - Render Compiled (runtime execution order) preview:
//   - Draw StepSpec.compiled list in a scroll view
//   - Track original source location via OriginMap (track/index mapping)
//   - Display drift/missing warnings for mismatches/loss
//   - Clicking an entry jumps to the original command (track switch + selection/scroll sync)
//
// Good places to modify here
// - Add/adjust Step fields (metadata/tags/notes)
// - Gate foldout policy and preset apply behavior
// - Track tab UX (selection preservation, scroll policy on tab change)
// - Compiled Preview formatting/height/warning rules (drift/missing)
//
// Related dependencies (provided by other partials)
// - EnsureCommandsList(), HandleCommandShortcuts(): commands list + shortcuts
// - DrawGateHeaderRow_WithDefaultDropdown(), DrawGateInline(): gate UI
// - BuildOriginMapForStep(), TryGetOrigin(), SummarizeCompiledLine(): origin mapping & display
// - TrackToIndex()/IndexToTrack(): tab index conversion
//
// -------------------------------------------------------------------------------------------------
// [4] Summary & Utility — summary strings / origin mapping / compiled line generation
//
// Responsibilities
// - Generate summary strings for UI
//   - GateToken summary: SummarizeGate()
//   - One-line command summary: SummarizeCommand(), GetManagedRefTypeName()
//
// - Map “original location (track/index)” between track lists and compiled list
//   - BuildOriginMapForStep(): managedReferenceId -> (track, index)
//   - TryGetOrigin(): find origin of a compiled element
//
// - Build compiled-preview display lines
//   - TryReadMeta(): read track/phase/blocking/infinite/duration from meta (_meta/meta/Meta)
//   - SummarizeCompiledLine(): compare origin vs meta -> drift/missing indicators
//
// Assumptions / notes
// - Command lists must be SerializeReference ManagedReference to track via managedReferenceId.
// - meta lookup allows "_meta"/"meta"/"Meta" and depends on internal field names (track/phase/hints).
//
// Good places to modify here
// - Summary formats (e.g., "Delay(0.5s)", "Signal('X')", "#3 Fade (screen/role)")
// - Compiled Preview badges/hints/warning rules
// - When track structure changes (field names/order), review TrackFieldNames/TrackTypes and origin scan logic
//
// -------------------------------------------------------------------------------------------------
// [5] Commands Panel (ReorderableList) — row rendering / context menus / reorder
//
// Responsibilities
// - Build/cache a ReorderableList bound to the active track’s commandsProp (SerializeReference array)
// - Row rendering
//   - striped background + selection highlight + separators
//   - foldout (expand/collapse) + one-line summary + expanded body rendering
//   - expanded body is drawn by iterating ManagedReference fields directly (not relying on isExpanded)
//
// - Context menu (right-click)
//   - Header/empty: add at index 0 (single/batch)
//   - Row: add after this row + delete
//
// - Reorder callbacks
//   - ApplyModifiedProperties + SetDirty + ForceCompileAll + Repaint
//
// Good places to modify here
// - Row UI (padding/colors/summary label/expanded body policy)
// - Menu policy (insert location, items, batch presets)
// - Reorder side-effects (compile frequency/timing, selection/scroll retention)
//
// Assumption
// - This editor expects SerializeReference polymorphic lists (validated via IsSerializeReferenceCommandList).
//
// -------------------------------------------------------------------------------------------------
// [6] Foldout State Management — stable expand/collapse UI for SerializeReference lists
//
// Goal
// - SerializedProperty.isExpanded is unreliable when lists rebuild; treat foldout state as “editor UI state”
//   and maintain it via separate caching/persistence.
//
// Key idea
// - (commands list propertyPath) + (managedReferenceId) -> expanded(bool)
//
// Responsibilities
// 1) Runtime cache
//    - _commandFoldoutsByPath: per commandsPath map of (id->bool)
//    - GetFoldoutMap(): ensures a map exists
//
// 2) Preserve state across mutations
//    - SnapshotCommandFoldouts(): capture current state
//    - RestoreCommandFoldouts(): restore + prune stale ids
//    - newIdToCollapse: supports “new commands default collapsed” UX
//
// 3) Bulk toggles
//    - SetAllCommandFoldouts(): expand/collapse one list
//    - SetAllCommandFoldouts_ForCurrentNode(): expand/collapse all steps/tracks in current node
//
// 4) Persistence per asset
//    - Key: FoldoutKeyPrefix + targetSequence GUID
//    - Save/Load as JSON to SessionState (session) + EditorPrefs (sticky)
//
// Good places to modify here
// - Key policy (per-asset vs global, propertyPath normalization)
// - Default state policy (new/first-seen commands expanded vs collapsed)
// - Prune aggressiveness and timing
// - “Expand/Collapse All” scope (list vs node vs entire sequence)
//
// -------------------------------------------------------------------------------------------------
// [7] Command Insertion / Add Menu / Type Creation — “final insertion sink”
//
// Responsibilities
// - InsertSingleAt / InsertBatchAt / InsertCommandFactoryAt
//   - Insert at index
//   - Assign managedReferenceValue to new instance
//   - Normalize meta.track + apply defaults + auto-fill roleKey (optional)
//   - Foldout snapshot/restore + new items default collapsed
//   - Reserve selection/scroll (_pendingCommandIndex, _scrollToNewCommand)
//
// - ShowCommandAddMenu
//   - Cache command types; prefer hook (SequenceEditorMenuHooks)
//   - Fallback to GenericMenu
//   - extendMenu allows caller to append items (e.g., Delete)
//
// - CreateCommandInstance
//   - Activator.CreateInstance
//   - Inject defaults via CommandMetaDefaults.GetDefault(t) (best-effort)
//   - Auto-fill roleKey from current Role slot if enabled
//
// - Meta synchronization (important)
//   - NormalizeInsertedCommandMeta: force serialized meta.track to active track
//   - SyncMetaAfterInsert: also sync the actual instance meta via Editor_SetMeta
//
// Good places to modify here
// - Insert position / selection / scroll policy
// - Default foldout state for new commands, meaning of expandNew/scroll flags
// - Defaults/meta policy, auto-fill expansion (e.g., screenId)
// - Menu grouping / batch presets / hook priority
//
// -------------------------------------------------------------------------------------------------
// [8] Clipboard (Copy/Paste) — JSON round-trip for Commands/Steps
//
// Goal
// - Store CommandSpecBase / StepSpec as JSON in systemCopyBuffer and restore later.
// - Use Box ScriptableObject wrappers for stability with SerializeReference polymorphism.
//
// Flow
// - Copy: CreateInstance(Box) -> assign -> ToJson -> Prefix+json -> DestroyImmediate
// - Paste: check prefix -> extract json -> CreateInstance(Box) -> FromJsonOverwrite -> return -> DestroyImmediate
//
// This part owns
// - Clipboard format + serialization/deserialization only
// - Insert location/foldout/scroll post-processing belongs to insertion/shortcut layers
//
// Good places to modify here
// - Prefix policy (version tags, compatibility)
// - Robust validation/logging/type checks
// - Packaging extra metadata (extend Box types if needed)
//
// -------------------------------------------------------------------------------------------------
// [9] Data Constructors & Deep Clone — blank defaults + safe duplicates
//
// Responsibilities
// - CreateBlankNode / CreateBlankStep: default structures for “Add Node/Step”
// - SanitizeGate: clear type-incompatible fields + prevent nulls
// - CloneNodeDeep / CloneStepDeep / CloneCommandDeep
//   - Command deep clone via JSON round-trip (SerializeReference-friendly)
//   - tracks cloned into new StepTracks; compiled is created empty (expected to be rebuilt by compile)
//
// Policy notes
// - if type != Delay -> seconds=0; if type != Signal -> signalKey=""; keep signalKey non-null
// - if gate == Immediately during clone -> replace with defaultGate to keep consistent editing defaults
//
// Good places to modify here
// - Default values for newly created items
// - Duplicate include/exclude policy
// - Command cloning mechanism (performance/custom cloning)
//
// -------------------------------------------------------------------------------------------------
// [10] Gate Defaults + RoleKey Slots — default gate preset & roleKey autofill/bulk assign
//
// Goals
// - Maintain a “global editor preset” gate for new steps (EditorPrefs)
// - Keep up to 9 RoleKey slots for fast injection and bulk assignment
// - Stabilize commit UX (Enter/FocusLost) and persist user-local preferences
//
// Gate Defaults (EditorPrefs)
// - Default gate used when creating NEW steps:
//   - Type / Seconds / SignalKey
//   - Save policy: immediate save on Type change + save on Enter or focus loss for text/float fields
// - Apply Gate Preset (to current step)
//   - “Preset Type + Apply” overwrites THIS step’s gate
//   - Seconds/SignalKey are sourced from Gate Defaults (Type is sourced from the preset dropdown)
//
// RoleKey Slots (EditorPrefs)
// - Slot input (RoleKey text fields) + “Set RoleKey” bulk apply
//   - Apply roleKey to commands in the current step
//   - Scope policy: CurrentTrack vs AllTracks (stored in EditorPrefs)
// - Auto-fill roleKey on Add Command
//   - Auto target = selected slot index
//   - Auto-fill is enabled/disabled by a toggle in the header
// - Persistence model
//   - Working state (current slots + visible slot count) is stored in EditorPrefs
//     - RoleSlots.Count, RoleSlots.Json
//   - Slot list is normalized to RoleSlotMaxCount (9) when saving/loading
//
// Good places to modify here
// - Gate Defaults commit policy, UI sizing/layout
// - Apply behavior (type-only vs full overwrite)
// - Role slot UX and auto-injection targets (extend to other fields)
// - Bulk apply scope (all tracks in step vs active track only)
// - Role slot count UI + hotkeys (select auto target, apply slot via shortcuts)
//
// -------------------------------------------------------------------------------------------------
// [11] Keyboard Navigation — 3 columns (Nodes/Steps/Commands) + track switching
//
// Responsibilities
// - Ignore navigation keys when typing in text fields (avoid input conflicts)
// - Update 3-column navigation state via ←->↑↓/Space/Ctrl(or Cmd)+E
// - Include track left/right switching in Commands column
// - Auto-scroll to keep selection visible (EnsureSelectedCommandVisible)
// - Delegate actual deletion to CRUD utilities (clear separation of authority)
//
// Good places to modify here
// - Shortcut mapping/policy (HandleArrowNavigation, DeleteByActiveColumn, etc.)
// - Column entry rules & selection retention
// - Track switching + selection/scroll retention behavior in Commands column
//
// -------------------------------------------------------------------------------------------------
// [12] Shortcut-driven Editing (Commands/Steps) — Copy/Paste/Duplicate/Delete/Quick Add
//
// Responsibilities
// - Route list-context shortcuts into CRUD calls.
// - Examples:
//   - Delete: delete selected command/step
//   - Enter: toggle foldout
//   - Shift+Enter: toggle all foldouts in list
//   - Space: Quick Add (open +Command menu)
//   - Ctrl+C/X/V/D: copy/cut/paste/duplicate
//
// Design note
// - This layer interprets input and calls utilities.
//   Real data mutation ownership remains in the CRUD pipeline utilities.
//
// -------------------------------------------------------------------------------------------------
// [13] CRUD (Data Mutation) Pipeline — Undo / Dirty / DelayModify / deletion rules
//
// Responsibilities
// - Perform actual Add/Delete/Duplicate safely and consistently
// - Wrap edits in DelayModify to avoid GUI event conflicts (EditorApplication.delayCall pattern)
// - Handle Unity serialization edge cases for SerializeReference deletion (“sometimes needs double delete”)
// - After deletion: move selection, invalidate/rebuild lists, refresh compile outputs consistently
//
// Good places to modify here
// - Undo label / Dirty policy / compile trigger timing
// - Next selection index rules after deletions
// - Track list discovery (when fields/structure change)
//
// -------------------------------------------------------------------------------------------------
// [14] Role Slots Presets (EditorPrefs) — “9 hot slots + infinite preset sets”
//
// Purpose
// - RoleKey 슬롯은 최대 9개(핫키/빠른 주입에 최적)로 고정한다.
// - 대신 “프리셋(세트)”를 여러 개 저장/로드하여, 사용자는 사실상 무한 슬롯처럼 느끼게 만든다.
// - 프리셋은 프로젝트 데이터가 아니라 개인 로컬(EditorPrefs)에 저장되는 ‘작업 환경 세팅’이다.
//
// Storage keys (EditorPrefs)
// - Active preset name:
//   - CPS.SequenceEditor.RoleSlots.Preset.Active
// - Preset index (names list):
//   - CPS.SequenceEditor.RoleSlots.Presets.IndexJson
//   - 이유: EditorPrefs는 키 열거(enumeration)가 불가능하므로, 이름 목록을 별도 JSON 인덱스로 관리한다.
// - Preset payload:
//   - CPS.SequenceEditor.RoleSlots.Preset.<PresetName>
// - AutoSave toggle:
//   - CPS.SequenceEditor.RoleSlots.Preset.AutoSave
//
// What a preset contains (policy)
// - roleSlotCount (visible slot count)
// - slots (RoleKey string list, normalized to RoleSlotMaxCount=9)
// - autoFillIdsOnAdd (Auto-fill(Role) toggle)
// - autoFillRoleSlotIndex (auto target slot index)
// - roleApplyScope (CurrentTrack / AllTracks)
// NOTE: Preset load overwrites current working state and immediately persists it back to “working prefs”
//       so that “what you see” == “what is saved” stays consistent.
//
// UI / UX (Preset Bar)
// - Preset: [Dropdown] [Save] [Save As] [Delete]
// - Dropdown change:
//   - Loads selected preset -> overwrites current role slots state -> writes working prefs
// - Save (overwrite active preset)
// - Save As (inline name input; no modal)
// - Delete (Default cannot be deleted)
// - AutoSave
//   - When ON, any change to role slots settings (count/scope/slot texts/auto target, etc.)
//     triggers automatic overwrite-save to the active preset.
//   - Recommended UX: disable the manual “Save” button when AutoSave is ON.
//
// Good places to modify here
// - Name sanitization rules (SanitizePresetName)
// - Preset payload schema evolution (RoleSlotsPresetBox fields)
// - AutoSave timing policy (per keystroke vs commit/focus lost)
// - Delete policy (confirmations, fallback behavior)
// - Optional future extension: Export/Import JSON for team sharing (since EditorPrefs is local-only)
//
// Related dependencies (from other partials)
// - Role slots working prefs: LoadRoleSlotsPrefs/SaveRoleSlotsPrefs/EnsureRoleSlotsCapacity
// - Header placement: DrawHeader() calls DrawRoleSlotsPresetBar + AutoSave toggle placement
// - AutoSave hook points: SaveRoleSlotsPrefs and RoleSlotsSettingsMini changes
