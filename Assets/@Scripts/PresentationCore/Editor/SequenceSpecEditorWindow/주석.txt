// =================================================================================================
// SequenceSpecEditorWindow — 통합 주석 가이드
//
// 목적
// - 이 파일은 SequenceSpecSO(노드/스텝/트랙/커맨드)를 편집하는 Unity EditorWindow의 “전체 구조 안내서”다.
// - 실제 구현은 partial로 여러 파일에 흩어져 있어도, 아래 주석을 따라가면
//   “어디가 무엇을 담당하는지 / 무엇을 고칠 때 어디를 봐야 하는지”가 한 번에 복원되도록 한다.
//
// 큰 그림(에디터가 다루는 데이터)
// - SequenceSpecSO
//   - sequenceKey
//   - nodes : List<NodeSpec>
//     - NodeSpec.editorName
//     - NodeSpec.steps : List<StepSpec>
//       - StepSpec.editorName
//       - StepSpec.gate : GateToken
//       - StepSpec.tracks : StepTracks
//         - interaction/setup/motion/dialogue/fx : List<CommandSpecBase> (SerializeReference)
//       - StepSpec.compiled : List<CommandSpecBase> (runtime order preview, SerializeReference)
//
// 화면/UX(에디터 레이아웃)
// - 상단: Toolbar (타겟 선택, 검색, Ping, 단축키 팝업)
// - 헤더: sequenceKey, Auto-fill(Role), Gate Defaults, RoleKey 슬롯, 경고
// - 좌측: Nodes 리스트(+ 멀티삭제 UI)
// - 우측: Steps 리스트 + Step 디테일 + Commands + Compiled Preview + 하단 Command Bar
//
// 공통 설계 원칙
// - SerializeReference(ManagedReference) 커맨드 리스트를 “안정적으로” 다루기 위해:
//   - ReorderableList는 propertyPath 캐싱 + 필요 시 null로 무효화하여 재생성한다.
//   - Foldout(펼침/접힘) 상태는 SerializedProperty.isExpanded를 믿지 않고 별도 캐시/저장한다.
// - 데이터 변경은 GUI 이벤트 충돌을 피하기 위해 DelayModify()로 래핑하는 패턴을 우선한다.
// - 변경 적용은 Undo/Dirty/Apply/Compile/Repaint가 일관된 파이프라인을 따르도록 유지한다.
//
// -------------------------------------------------------------------------------------------------
// [0] 메인 윈도우(권위자) — 생명주기/바인딩/전역 정책
//
// 이 영역의 책임(큰 권위)
// - EditorWindow 생명주기(OnEnable/OnDisable/OnGUI/OnSelectionChange)
// - targetSequence(SequenceSpecSO) 바인딩(_so, _sequenceKeyProp, _nodesProp)
// - 전역 UI 상태:
//   - 선택/네비게이션: _navColumn, _selectedNode, _selectedStep, _activeTrack
//   - 리스트 캐시: _nodesList/_stepsList/_commandsList, _stepsPropPath/_commandsPropPath
//   - 스크롤/점프: _nodesScroll/_rightScroll/_compiledScroll, _scrollToNewCommand 등
// - 전역 입력(키보드 네비게이션/삭제) 라우팅
// - “값 변경 시 컴파일 갱신” 같은 정책 결정(ApplyModifiedProperties -> ForceCompileAll)
//
// 여기서 바꾸면 좋은 것
// - 창 초기화 순서(LoadPreferences/LoadFoldouts/RebuildIfNeeded 호출 순서)
// - targetSequence 교체 시 리빌드 강도(force)와 캐시 무효화 범위
// - ApplyModifiedProperties 후 SetDirty/Compile 정책(조건부 컴파일, 디바운스 등)
// - Track 시스템(탭/필드명/순서) 계약(TrackTabs/TrackFieldNames/TrackTypes)
//
// -------------------------------------------------------------------------------------------------
// [1] 레이아웃/그리기(툴바/헤더/패널 배치) — “화면 구성 전담”
//
// 담당 기능(Responsibilities)
// - DrawToolbar()
//   - SequenceSpecSO 타겟 선택(ObjectField) -> RebuildIfNeeded(force:true) + LoadFoldouts()
//   - 검색 필드(_searchField)
//   - Ping 버튼(에셋 Ping)
//   - 단축키 팝업(ShortcutsPopup)
//
// - DrawHeader()
//   - sequenceKey 표시/편집
//   - Auto-fill(Role) 토글(EditorPrefs 저장)
//   - Default Gate 바 + RoleKey 슬롯 바 배치
//   - 경고: sequenceKey 비었음, nodeCount=0 등
//
// - DrawNodesPanel()
//   - Node 리스트(스크롤 + ReorderableList)
//   - Add Node 버튼
//   - 멀티 삭제(Delete/Esc/체크 개수)
//
// - DrawRightPanel() / DrawNodeEditor()
//   - 선택된 Node의 Steps 리스트 + Step 단축키
//   - 선택된 Step 상세(게이트/트랙/커맨드)
//   - Compiled Preview + 하단 Command Bar(+Command, Node 단위 Expand/Collapse All)
//
// 여기서 수정하면 좋은 것
// - 전체 레이아웃(컬럼 폭, 여백, 스크롤 영역)
// - 헤더 컨트롤 위치/정렬(게이트/롤 위젯 배치)
// - 좌측/우측 패널 버튼 UX(+Node/+Step/+Command, 멀티삭제 UI)
// - 하단 바의 “Expand/Collapse All” 같은 범위 UI 구성
//
// 주의
// - 리스트 생성/데이터 수정 로직은 다른 파트가 권위자다.
//   여기서는 “그리기 + 호출”만 하고 실제 CRUD는 DelayModify/유틸로 위임하는 패턴을 유지하는 게 안전하다.
//
// -------------------------------------------------------------------------------------------------
// [2] ReorderableList 빌드/수명주기 — Nodes/Steps/Commands 바인딩/캐싱
//
// 이 영역의 책임
// - RebuildIfNeeded(force)
//   - _so/_sequenceKeyProp/_nodesProp 재구성
//   - 선택 인덱스 보존/클램프
//   - propPath 캐시 무효화(_stepsPropPath/_commandsPropPath 등)
//   - 리스트 캐시 무효화(_nodesList/_stepsList/_commandsList)
//   - (구조 변화 시) foldout 캐시 초기화/로드 정책과 맞추기
//
// - BuildNodesList()
//   - 좌측 Nodes 리스트 생성
//   - 멀티삭제 체크 UI(_deleteMultiMode/_checkedNodes)
//   - 검색 디밍(NodeMatchesSearch)
//   - 선택 변경 시 Steps/Commands 캐시 무효화
//
// - EnsureStepsList(nodeProp, stepsProp)
//   - 선택된 Node 기준 Steps 리스트 생성/캐시
//   - Step 요약(이름/editorName, gate 요약, compiled 수 등)
//   - 드래그 플래그(_isDraggingSteps) 관리
//   - 우클릭 메뉴/리오더 콜백(Dirty/Compile/Repaint)
//
// - NodeMatchesSearch()
//   - 검색 텍스트가 들어오면 노드 내부 Step/compiled/command 요약을 훑어 매칭 여부 판단
//
// 여기서 수정하면 좋은 것
// - Nodes/Steps 라벨/요약 포맷, 카운트 표시
// - 검색/필터 UX, 디밍 기준
// - 우클릭 메뉴(추가/복제/삭제) 정책, 삽입 위치 정책
// - 리빌드 조건/캐시 무효화 범위(“언제 다시 만들 것인가”)
//
// -------------------------------------------------------------------------------------------------
// [3] Step 디테일(오른쪽 패널) + Compiled Preview — “Step 편집 전담”
//
// 역할
// - 현재 선택된 Step(StepSpec)의 디테일을 그린다:
//   - Step Label(editorName)
//   - GateToken(gate) 편집 UI + Default Gate 드롭다운 연동
//   - Track 탭(Interaction/Setup/Motion/Dialogue/FX) 전환
//   - 선택된 Track의 Commands 리스트 렌더링 및 단축키 처리
//
// - Compiled(런타임 실행 순서) 결과를 미리보기로 보여준다:
//   - StepSpec.compiled 리스트를 스크롤 뷰로 출력
//   - OriginMap(트랙/인덱스 매핑)으로 “어느 원본 커맨드에서 왔는지” 추적
//   - drift/missing 표시로 불일치/유실을 경고
//   - 항목 클릭 시 원본 위치로 점프(트랙 전환 + 선택/스크롤 동기화)
//
// 여기서 수정하면 좋은 것
// - Step 디테일 UI 필드 추가(메타/태그/주석 등)
// - Gate UI 접기/펼치기 정책, 프리셋 Apply 정책
// - 트랙 탭 UX(전환 시 선택/스크롤 유지 정책)
// - Compiled Preview 포맷/높이/경고 기준(drift/missing)
//
// 관련 의존(다른 영역에서 제공)
// - EnsureCommandsList(), HandleCommandShortcuts(): 커맨드 리스트 구성/단축키
// - DrawGateHeaderRow_WithDefaultDropdown(), DrawGateInline(): Gate UI
// - BuildOriginMapForStep(), TryGetOrigin(), SummarizeCompiledLine(): Origin/표시
// - TrackToIndex()/IndexToTrack(): 탭 인덱스 변환
//
// -------------------------------------------------------------------------------------------------
// [4] Summary & Utility — 요약 문자열/Origin 매핑/Compiled 라인 생성
//
// 역할
// - UI에 표시할 “요약 문자열” 생성
//   - GateToken 요약: SummarizeGate()
//   - Command(ManagedReference) 한 줄 요약: SummarizeCommand(), GetManagedRefTypeName()
//
// - Track 리스트와 Compiled 리스트 사이 “원본 위치(트랙/인덱스)” 매핑
//   - BuildOriginMapForStep(): managedReferenceId -> (track, index)
//   - TryGetOrigin(): compiled element의 원본 찾기
//
// - Compiled Preview 표시 라인 생성
//   - TryReadMeta(): meta(_meta/meta/Meta)에서 track/phase/blocking/infinite/duration 읽기
//   - SummarizeCompiledLine(): meta vs origin 비교 -> drift/missing 표시
//
// 주의/전제
// - Command 리스트는 SerializeReference ManagedReference여야 managedReferenceId로 추적 가능
// - meta 탐색은 "_meta"/"meta"/"Meta" 3가지 이름을 허용하며 내부 필드명(track/phase/힌트)에 의존
//
// 여기서 수정하면 좋은 것
// - 요약 포맷(예: Delay(0.5s), Signal('X'), "#3 Fade (screen/role)")
// - Compiled Preview 배지/힌트/경고 기준
// - StepTracks 필드명/트랙 순서 변경 시 Origin 매핑 로직(TrackFieldNames/TrackTypes) 점검
//
// -------------------------------------------------------------------------------------------------
// [5] Commands 패널(ReorderableList) — 커맨드 행 렌더링/컨텍스트 메뉴/리오더
//
// 책임
// - 선택된 Step의 활성 Track 커맨드 배열(commandsProp)에 바인딩된 ReorderableList 생성/캐시
// - 행(Row) 렌더링
//   - 스트라이프 배경 + 선택 하이라이트 + 구분선
//   - foldout(펼침/접힘) + 한 줄 요약 + 확장 시 바디 렌더링
//   - 확장 시: isExpanded에 의존하지 않고 ManagedReference 내부 필드 직접 순회(높이/그리기)
//
// - 컨텍스트 메뉴(우클릭)
//   - 헤더/빈 영역: index 0에 추가(단일/배치)
//   - 행(Row): “이 행 다음에 추가” + “삭제”
//
// - 리오더 콜백
//   - ApplyModifiedProperties + SetDirty + ForceCompileAll + Repaint
//
// 여기서 수정하면 좋은 것
// - 행 UI(패딩/색/요약 라벨/확장 바디 표시 정책)
// - 메뉴 정책(삽입 위치, 메뉴 항목, 배치 추가 동작)
// - reorder 부수효과(컴파일 빈도/타이밍, selection/scroll 유지)
//
// 전제
// - SerializeReference 폴리모픽 리스트를 전제로 한다(IsSerializeReferenceCommandList)
//
// -------------------------------------------------------------------------------------------------
// [6] Foldout 상태 관리 — SerializeReference 커맨드 펼침/접힘 안정화 + 저장
//
// 목적
// - Unity의 SerializedProperty.isExpanded는 리스트 재생성 상황에서 흔들리므로,
//   foldout 상태를 “에디터 UI 상태”로 보고 별도 캐시/영속화를 제공한다.
//
// 핵심 아이디어
// - (commands 리스트 propertyPath) + (managedReferenceId) -> expanded(bool)
//
// 하는 일
// 1) 런타임 캐시
//    - _commandFoldoutsByPath : commandsPath 단위로 (id->bool) 유지
//    - GetFoldoutMap() : 맵 보장
//
// 2) 변경 작업 중 상태 보존
//    - SnapshotCommandFoldouts() : 스냅샷 생성
//    - RestoreCommandFoldouts() : 복원 + stale id prune
//    - newIdToCollapse 정책으로 “신규 커맨드는 기본 접힘” 같은 UX 가능
//
// 3) 일괄 토글
//    - SetAllCommandFoldouts() : 한 리스트 전체 펼침/접힘
//    - SetAllCommandFoldouts_ForCurrentNode() : 현재 노드의 모든 스텝/모든 트랙 일괄
//
// 4) 영속화(에셋 단위)
//    - FoldoutKeyPrefix + targetSequence GUID
//    - SessionState(세션) + EditorPrefs(영구) JSON 저장/복원
//
// 여기서 수정하면 좋은 것
// - 키 정책(per-asset vs 전역, propertyPath 정규화 여부)
// - 기본값(신규/초기 상태 펼침/접힘)
// - prune 강도/시점
// - Expand/Collapse All 범위(현재 리스트/현재 노드/전체 시퀀스)
//
// -------------------------------------------------------------------------------------------------
// [7] Command 삽입/추가 메뉴/타입 생성 — “삽입의 최종 도착지”
//
// 역할
// - InsertSingleAt / InsertBatchAt / InsertCommandFactoryAt
//   - 지정 위치에 커맨드 삽입
//   - managedReferenceValue에 새 인스턴스 할당
//   - 메타(track) 정규화 + defaults + roleKey 자동 채움(옵션)
//   - foldout snapshot/restore + 신규 항목 기본 접힘
//   - 선택/스크롤 예약(_pendingCommandIndex, _scrollToNewCommand)
//
// - ShowCommandAddMenu
//   - 타입 캐시 + 훅(SequenceEditorMenuHooks) 우선 위임
//   - 폴백 GenericMenu 제공
//   - extendMenu로 Delete 같은 항목 확장 가능
//
// - CreateCommandInstance
//   - Activator.CreateInstance
//   - CommandMetaDefaults.GetDefault(t) 주입(실패해도 무시)
//   - Auto-fill(Role) 정책에 따라 roleKey 자동 주입
//
// - 메타 동기화(중요)
//   - NormalizeInsertedCommandMeta: SerializedProperty 상 meta.track 강제 정렬
//   - SyncMetaAfterInsert: 실제 인스턴스 내부 meta도 Editor_SetMeta로 동기화
//
// 여기서 수정하면 좋은 것
// - 삽입 위치/선택/스크롤 정책
// - 신규 foldout 기본값, expandNew/scroll 의미
// - defaults/meta 정책, auto-fill 확장(screenId 등)
// - 메뉴 구성/그룹핑/배치 프리셋
//
// -------------------------------------------------------------------------------------------------
// [8] 클립보드(Copy/Paste) — JSON 직렬화 기반 Command/Step 복원
//
// 목적
// - CommandSpecBase / StepSpec를 JSON으로 systemCopyBuffer에 저장하고 복원
// - SerializeReference 다형 타입을 안전하게 다루기 위해 Box ScriptableObject 래핑 사용
//
// 동작
// - Copy: Box CreateInstance -> box에 넣기 -> ToJson -> Prefix+json 저장 -> DestroyImmediate
// - Paste: prefix 확인 -> json 추출 -> Box CreateInstance -> FromJsonOverwrite -> spec/step 반환 -> DestroyImmediate
//
// 이 파트가 책임지는 것
// - “클립보드 포맷”과 “직렬화/역직렬화”
// - 실제 삽입 위치/폴드아웃/스크롤 후처리는 삽입/단축키 파트가 담당
//
// 여기서 수정하면 좋은 것
// - prefix 정책(버전 태그, 호환성 처리)
// - 유효성/예외 처리 강화(로그, 타입 검증)
// - 추가 메타 동봉(필요 시 Box 구조 확장)
//
// -------------------------------------------------------------------------------------------------
// [9] 데이터 생성/깊은 복제 — Step/Node 기본 생성 + Duplicate 안정화
//
// 역할
// - CreateBlankNode / CreateBlankStep : 새 항목 기본 구조 생성
// - SanitizeGate : GateToken 타입에 맞지 않는 필드 정리 + null 방지
// - CloneNodeDeep / CloneStepDeep / CloneCommandDeep
//   - JSON round-trip으로 Command 깊은 복제(SerializeReference 대응)
//   - tracks는 새 StepTracks로, compiled는 빈 리스트로 생성(컴파일에서 다시 채움 기대)
//
// 정책 포인트
// - Delay가 아니면 seconds=0, Signal이 아니면 signalKey=""
// - gate가 Immediately이면 복제본 gate를 defaultGate로 교체(편집 기본값 일관성)
//
// 여기서 수정하면 좋은 것
// - “새로 만들 때 기본값”
// - Duplicate 시 포함/제외 필드 정책
// - 커맨드 복제 방식(성능/커스텀 복제)
//
// -------------------------------------------------------------------------------------------------
// [10] Gate Defaults + RoleKey 슬롯 — 기본 Gate 프리셋 & roleKey 자동 채움/일괄 적용
//
// 목표
// - 새 Step 생성 시 기본 Gate를 “에디터 전역 프리셋”처럼 유지(EditorPrefs)
// - 자주 쓰는 RoleKey를 “최대 9개 슬롯”으로 유지하고, 빠른 주입/일괄 적용을 제공
// - 저장/커밋 타이밍을 안정화(Enter/FocusLost)하여 “입력 후 저장 누락”을 방지
//
// Gate Defaults (EditorPrefs)
// - 새 Step 생성 시 기본으로 복사되는 GateToken
//   - Type / Seconds / SignalKey
// - 저장 정책
//   - Type 변경: 즉시 저장
//   - Seconds/SignalKey 입력: Enter(Commit) 또는 포커스 이탈(FocusLost) 시 저장
// - Apply Gate Preset (현재 Step에 적용)
//   - “Preset Type + Apply”로 현재 Step gate를 덮어쓴다
//   - Type은 Preset dropdown에서, Seconds/SignalKey는 Gate Defaults에서 가져온다
//
// RoleKey Slots (EditorPrefs, Working State)
// - 슬롯 텍스트 입력(RoleKey string) + “Set RoleKey” 버튼(일괄 적용)
//   - 현재 Step의 커맨드들에 roleKey를 일괄 적용
//   - 적용 범위(scope): CurrentTrack vs AllTracks (EditorPrefs 저장)
// - Auto-fill(Role) 기능
//   - 새 커맨드 추가 시 roleKey 자동 주입
//   - Auto 타겟 = 선택된 슬롯 인덱스(1~9 핫키 등으로 바꿀 수 있음)
// - 저장 모델(중요)
//   - 슬롯 문자열 전체(최대 9개)는 JSON으로 EditorPrefs에 저장된다
//   - 화면에 “몇 칸을 보여줄지”(_roleSlotCount)는 별도 Count로 저장된다
//   - 즉, 표시 슬롯 수를 줄여도 값은 리스트/JSON에 남아있고 다시 늘리면 복원된다
//
// 여기서 수정하면 좋은 것
// - Gate Defaults 저장/커밋 정책, UI 폭/배치
// - Apply 시 덮어쓸 필드 범위(타입만/전체)
// - Role 슬롯 UI(슬롯 개수/표현), auto-fill 주입 대상 필드 확장(roleKey 외 screenId 등)
// - 일괄 적용 범위(scope) 정책(CurrentTrack/AllTracks)
// - 핫키 UX(예: 숫자 1~9로 Auto 슬롯 선택, Shift+1~9로 해당 슬롯을 Step에 적용)
//
// -------------------------------------------------------------------------------------------------
// [11] 키보드 네비게이션 — 3열(Nodes/Steps/Commands) 이동 + 트랙 이동
//
// 역할
// - 텍스트 입력 중 충돌 방지(EditingTextField 시 무시)
// - ←->↑↓/Space/Ctrl(or Cmd)+E 같은 키로 3열 네비게이션 상태 업데이트
// - Commands 컬럼에서는 트랙(_activeTrack) 좌/우 이동 포함
// - 선택 이동 시 스크롤 자동 보정(EnsureSelectedCommandVisible)
// - “컬럼 단위 삭제” 단축키는 데이터 삭제 유틸에 위임(권위 분리)
//
// 여기서 수정하면 좋은 것
// - 단축키 매핑/정책(HandleArrowNavigation, DeleteByActiveColumn 등)
// - 컬럼 진입 조건/선택 유지 규칙
// - Commands 컬럼 트랙 이동/선택 유지/스크롤 정책
//
// -------------------------------------------------------------------------------------------------
// [12] 단축키 기반 편집(Commands/Steps) — Copy/Paste/Duplicate/Delete/Quick Add
//
// 역할
// - 커맨드/스텝 리스트 단축키를 “CRUD 호출”로 라우팅
// - 예:
//   - Delete: 현재 선택 커맨드/스텝 삭제
//   - Enter: foldout 토글
//   - Shift+Enter: 리스트 전체 foldout 토글
//   - Space: Quick Add(+Command 메뉴 등)
//   - Ctrl+C/X/V/D: 복사/잘라내기/붙여넣기/복제
//
// 설계 메모
// - 이 파트는 “입력 해석 -> 유틸 호출”이 책임이고,
//   실제 데이터 수정(Undo/SerializedObject/Compile)은 CRUD 유틸 파트가 권위자다.
//
// -------------------------------------------------------------------------------------------------
// [13] CRUD(데이터 변경) 파이프라인 — Undo/Dirty/DelayModify/삭제 규칙
//
// 역할
// - Add/Delete/Duplicate 같은 실제 데이터 변경을 안전하게 수행
// - DelayModify로 GUI 이벤트 충돌 회피(EditorApplication.delayCall 기반)
// - SerializeReference 삭제 시 “2회 Delete 필요” 같은 Unity 직렬화 특수 케이스 처리
// - 삭제 후 선택 이동/리스트 재빌드/컴파일 갱신을 일관되게 수행
//
// 여기서 수정하면 좋은 것
// - Undo 라벨/Dirty 정책/컴파일 트리거 타이밍
// - 삭제 후 다음 선택 인덱스 규칙
// - 트랙 리스트 탐색 방식(필드명/구조 변경 대응)
// -------------------------------------------------------------------------------------------------
// [14] Role Slots Presets(세트 저장/로드) — “9개 핫 슬롯 + 프리셋으로 무한 세트”
//
// 목적
// - RoleKey 슬롯은 최대 9개(핫키/빠른 주입에 최적)로 제한한다.
// - 대신 “프리셋(세트)”를 여러 개 저장/로드하여, 사용자는 사실상 무한 슬롯처럼 쓰게 만든다.
// - 프리셋은 프로젝트 데이터가 아니라 개인 로컬(EditorPrefs)에 저장되는 “작업 환경 세팅”이다.
//
// 저장 구조(EditorPrefs 키 정책)
// - 활성 프리셋 이름
//   - CPS.SequenceEditor.RoleSlots.Preset.Active
// - 프리셋 이름 목록(인덱스) JSON
//   - CPS.SequenceEditor.RoleSlots.Presets.IndexJson
//   - 이유: EditorPrefs는 키 열거가 불가능하므로, 이름 목록을 별도 JSON 인덱스로 관리한다.
// - 프리셋 본문(JSON payload)
//   - CPS.SequenceEditor.RoleSlots.Preset.<PresetName>
// - AutoSave 토글
//   - CPS.SequenceEditor.RoleSlots.Preset.AutoSave
//
// 프리셋이 포함하는 값(스키마/정책)
// - roleSlotCount(표시 슬롯 수)
// - slots(최대 9개 RoleKey 문자열 리스트, 항상 RoleSlotMaxCount로 정규화)
// - autoFillIdsOnAdd(Auto-fill(Role) 토글)
// - autoFillRoleSlotIndex(자동 주입 대상 슬롯 인덱스)
// - roleApplyScope(CurrentTrack / AllTracks)
// - 프리셋 Load는 “현재 작업 상태(Working Prefs)”를 덮어쓴 뒤,
//   즉시 Working Prefs에도 저장해서 “화면에 보이는 상태 == 저장된 상태”를 유지한다.
//
// UI/UX(Preset Bar)
// - Preset: [Dropdown] [Save] [Save As] [Delete]
// - Dropdown 변경: 선택 프리셋 Load -> 현재 상태 덮어쓰기 -> Working Prefs 저장
// - Save: 활성 프리셋에 현재 상태를 덮어쓰기 저장
// - Save As: 새 이름으로 프리셋 생성(인라인 입력)
// - Delete: 활성 프리셋 삭제(Default는 삭제 불가)
// - AutoSave
//   - ON이면 슬롯 텍스트/슬롯수/Scope/Auto 타겟 등 변경 시 활성 프리셋을 자동으로 덮어쓰기 저장
//   - 권장 UX: AutoSave ON일 때는 수동 Save 버튼을 비활성화(중복 행동 방지)
//
// 여기서 수정하면 좋은 것
// - 프리셋 이름 정규화 규칙(SanitizePresetName)
// - 프리셋 payload 스키마 확장(추가로 저장할 필드가 생길 때)
// - AutoSave 트리거 정책(키 입력마다 vs 커밋/포커스 이탈 시점)
// - Delete 확인/폴백 정책(Default 처리)
// - 팀 공유가 필요해지면 Export/Import(JSON) 같은 기능으로 확장 가능(현재는 EditorPrefs 로컬 전용)
