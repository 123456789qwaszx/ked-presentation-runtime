## 목표 한 문장

> 이모지는 **캐릭터 슬롯의 한 자리에 붙는 작은 리그**다. 그림은 키로 고르고, 움직임은 모션 툴이 만든 모션이며, 수명은 "한 번"(이벤트)이거나 "머무름"(상태)이다.

이모지 전용 코드를 최소로 두고, 그 밑의 셋 — **캐릭터가 아닌 리그 종류 · 리그를 다른 리그의 노드에 붙이기 · 어느 리그에서나 도는 모션** — 을 기반으로 세운다. 같은 기반에 나중에 소품 · 컷인 장식이 올라간다.

## 0. 지난 일 — 한 번 만들었다가 지웠다

- 이모지 서브시스템은 캐릭터 리그 **안에** 노드 39개로 있었고, 절차적 연기 계열과 함께 삭제됐다(`Core/Documentation~/target-boundary.md`, `ExportedTuning/schema.md`). 캐릭터마다 39개 노드를 지고 다녔고, 계층을 고칠 때마다 프리팹 · 덤프가 갈렸다.
- 남은 것: 그림 34장(`Samples/Content/Art/Emoji` — 프레임 묶음 `말줄임점풍선-1~4`, 좌 · 우 판 포함), 쓰이지 않는 재질 · 셰이더(`EmojiVisual`), 캐릭터별 얼굴 옆 자리 값(`CharacterFocusOffsetSet.faceAura`).
- 이번에는 캐릭터 리그를 **건드리지 않는다.** 이모지는 필요할 때 서고 끝나면 사라지는 별도 리그다.

## 3. 기반 셋

### 3.1 리그 종류 `emoji` — 스키마와 덤프

`CharacterRigSchema`와 같은 방식(코드가 소유 · 덤프로 내보냄).

```
Emoji_Anchor      자리 — 쪽(좌 · 우)과 미세 조정. 런타임이 놓는다. 모션은 건드리지 않는다. CanvasGroup(불투명도)
  Emoji_Body      묶음 전체의 위치 · 회전 · 배율 — 튀어나옴 · punch · 흔들림
    Emoji_Part1          조각 — 위치 · 회전 · 배율. 모션이 움직인다
      Emoji_Part1_Image  조각 그림(Image) — 놓임(정의의 x · y · scale · rotation). 모션은 건드리지 않는다. 원본 픽셀 크기 × 정의의 배율
    Emoji_Part2 › Emoji_Part2_Image
    …
    Emoji_Part6 › Emoji_Part6_Image   (조각은 여섯 — §8-5)
```

- **조각(Part)** — 이모지 하나가 그림 여러 장을 따로 움직이는 경우가 있다(원본의 분홍 꽃). 조각마다 노드를 두고 모션이 조각을 따로 움직인다. 그림이 한 장인 이모지는 `Part1`만 쓰고 나머지는 꺼 둔다.
- **놓임과 움직임은 다른 노드다**(§8-8). 조각이 그 이모지에서 원래 놓이는 자리(꽃 넷이 흩어진 자리)는 `_Image` 노드에, 모션은 `Part` 노드에 들어간다 — 같은 노드면 모션의 첫 키가 놓임을 지운다. 캐릭터 리그가 배역 보정(`VisualOffset`)과 연기 축을 가른 것과 같은 까닭이다. `_Image` 노드는 모션 채널을 받지 않는다.
- **값(2026-11-11)**: 전부 가운데 앵커 · 가운데 피벗(제 중심에서 튀어나오고 줄어든다). 조각 노드와 그림 노드는 160×160, 나머지는 크기 없는 축 노드. 불투명도(CanvasGroup)는 `Emoji_Anchor`에만 있고 0으로 태어난다. 그림 노드의 `Image`는 그림이 꽂히기 전에는 꺼져 있다.
- 모션이 겨눌 수 있는 노드는 `Emoji_Body`와 `Emoji_PartN`이다(`EmojiRigSchema.MotionNodeIds`) — 모션 로더가 `rig: "emoji"` 클립을 이것으로 검증한다(`MotionLibrary.Parse`의 리그별 목록 · `MotionRigSchemas`).
- 리그 종류 하나에 스키마 하나라 조각 수는 고정이다(모션 로더가 노드 id를 스키마로 검증한다).
- **한 노드가 위치 · 회전 · 배율을 모두 받는다.** 캐릭터 리그의 "한 노드 = 한 축"은 여러 커맨드가 같은 인물을 나눠 잡기 때문에 있는 규약이다. 이모지 리그는 재생기 하나만 잡으므로 축을 노드로 쪼갤 까닭이 없고, 쪼개면 조각마다 노드가 셋씩 는다. 모션 채널은 이미 (노드, 종류) 단위다.
- 익스포터(`PresentationTuningExporter`)가 `rigKind: "emoji"`를 덤프에 더한다. 덤프의 노드에 `hasImage`(그림을 그리는 노드인가)를 더한다 — 툴이 조각 그림을 어느 노드에 그릴지 이것으로 안다(툴의 코어 사본에 먼저 들어가 있는 필드와 같은 모양으로). 덤프 ↔ 실제 리그 등가 테스트(`RigSchemaTreeUnityParityTests`)에 한 갈래를 더한다.
- 모션 로더(`MotionLibrary`)는 이미 클립의 `rig`를 스키마로 검증한다 — `emoji` 스키마의 노드 id를 알려 주면 된다.

### 3.2 붙이기 — 캐릭터 리그의 노드를 부모로

이모지 리그는 캐릭터 슬롯의 노드 하나를 부모로 선다. 키 접두사는 `s1/emoji/`.

```
s1/CharSlot_… (배치 · 깊이 · 슬롯 배율)
  s1/CharSlot_Scale
    s1/CharacterPortrait_VisualOffset → … 연기 축 → 그림
    s1/emoji/Emoji_Anchor → …                ← 여기 (제안)
```

- **`CharSlot_Scale` 밑**(슬롯 계층의 마지막 노드). 배치 · 깊이 배율 · 슬롯 배율은 따라가고(멀리 선 인물의 이모지는 작다, 카드가 움직이면 같이 간다), 초상의 연기(끄덕임 · 흔들림)는 따라가지 않는다. 초상의 다음 형제라 자기 인물 위에 그려진다. 로케이터 노드는 두지 않는다(§8-1b).
- `Emoji_Anchor`의 자리 = 그 슬롯에 캐스팅된 캐릭터의 소켓 오프셋(기본 `faceAura`). 좌 · 우는 x 부호를 뒤집는다. **뜨는 순간 한 번** 푼다 — `place`와 같은 표 · 같은 풀이(`FocusOffsetMath.Resolve` · `SettledFocusMath.SolveFocusPlacement`)로, 정착한 무대에서. 떠 있는 동안 다시 풀지 않는다.
- 캐릭터 리그 스키마는 한 줄도 바뀌지 않는다. 런타임은 `EmojiRigBuilder`가 리그를 세워 그 노드 밑에 넣고, 코어는 `AddRigTo(…, attachParentKey: "s1/CharSlot_Scale")`로 같은 트리를 낸다(모션 툴의 미리보기도 같은 함수).

### 3.3 모션 — 어느 리그에서나, 그리고 반복

`MotionCommandCharR`의 몸통(시작값 → 채널 샘플링 → 끝 확정)을 **리그를 모르는 재생기**로 뺀다. 입력은 "노드 id → `RectTransform`"을 주는 조회 하나다. 캐릭터 모션 커맨드는 그 재생기를 쓰는 얇은 껍질로 남고 동작은 같다.

- **반복**: 재생기에 "끝나면 처음부터"를 더한다. 모션 규약(`motions/2`)은 그대로다 — 반복은 모션이 아니라 **쓰는 쪽**(이모지 정의)이 정한다. mode가 커맨드의 인자인 것과 같은 꼴이다. 주기적 punch = 길이가 주기인 `restore` 모션(예: 0.2초 punch + 1.3초 쉼)의 반복.
- **불투명도 · 그림 교체**: 모션 규약에 넣지 않는다(§8-4). 등장 · 퇴장 페이드와 프레임 넘기기(`말줄임점풍선-1~4`)는 이모지 정의의 값이고 이모지 재생기가 돈다. 규약에 넣으면 툴 · 코어 · 리듀서 · 장부가 모두 바뀐다.

## 4. 이모지 정의

키 하나가 가리키는 것. **정의는 모션 툴이 내는 `emojis.json`이고 런타임이 읽는다**(§8-7 — `motions.json`과 같은 길). 형식은 이 표가 정하고 툴이 맞춘다. 유니티에서 정의를 고치지 않는다.

| 값 | 뜻 | 예 |
|---|---|---|
| `key` | 대본이 부르는 이름 | `sweat` |
| `parts[]` | 조각마다: 그림(`frames` — 여러 장이면 `fps`로 넘긴다) · 좌우 판이 따로 있으면 둘. 조각이 하나면 그림 한 벌. 놓임(`x` · `y` · `scale` · `rotation` — 없으면 제자리, §3.1) | `05_삐질삐질땀방울-1~3`, 8 |
| `scale` | 원본 픽셀에 곱하는 배율 | 1.0 |
| `socket` · `side` · `offset` | 붙는 자리 · 기본 쪽 · 미세 조정 | `faceAura`, right, (0, 0) |
| `in` | 등장 모션 이름 + 페이드 시간 | `emoji_pop`, 0.1s |
| `loop` | 머무는 동안 반복하는 모션(없으면 가만히) | `emoji_punch` |
| `out` | 퇴장 모션 이름 + 페이드 시간 | `emoji_out`, 0.15s |
| `hold` | "한 번"일 때 등장 뒤 머무는 시간 | 1.0s |

모션 셋(`in` · `loop` · `out`)은 `motions.json`의 `rig: "emoji"` 클립이다. 이모지마다 따로 만들 수도, 공용을 돌려 쓸 수도 있다.

## 5. 대본

```yarn
<<emoji s1 sweat>>              // 한 번 — 등장 → hold → 퇴장. 기다리지 않는다
<<emoji s1 question left>>      // 쪽을 바꿔서
<<emoji_on s1 zzz>>             // 머무름 — 등장 뒤 loop를 돌며 떠 있다
<<emoji_off s1>>                // 퇴장
```

- 한 슬롯에 이모지 하나(조각은 여럿일 수 있다). 떠 있는 채로 다시 부르면 앞의 것을 즉시 치우고 새로 뜬다.
- "한 번"은 줄이 넘어가면 그 자리에서 끝난다(다른 커맨드의 스텝 수명과 같다). 줄 사이에 살아 있어야 하면 `emoji_on`이다.
- 표정과 함께 띄우는 것은 대본이 `face`와 `emoji`를 나란히 쓴다. 감정 하나로 표정 · 이모지 · 컷인 판 테마를 묶는 표는 §9 나중.

## 6. 수명 — 이벤트와 상태

| | 한 번 (`emoji`) | 머무름 (`emoji_on` / `emoji_off`) |
|---|---|---|
| 성격 | 이벤트 — 섬광 · 효과음과 같다 | 상태 — 팝업의 열림 · 닫힘과 같다 |
| 코어 폴드 | 무변 | 슬롯마다 `EmojiState { IsOn, Key, Side }` |
| 시크 통과 · 빨리 넘김 | 아무것도 남기지 않는다 | 끝값으로 놓는다 — 등장 없이 떠 있고 loop는 0초부터 |
| 되감기 · 로드 | 표적 줄의 것만 평소처럼 뜬다 | 루트부터 다시 접혀 같은 이모지가 떠 있다 |
| 정지 · 장면 경계 | 치운다 | 치운다(무대 Clear) |

- 폴드에 들어가는 것은 **"무엇이 떠 있나"뿐**이다. loop의 위상(지금 punch 중인가)은 정지 프레임의 사실이 아니다 — 등가 비교는 `EmojiState`만 본다. 이모지 리그의 노드는 코어 트리에 넣지 않는다(팝업과 같다).
- 슬롯을 다시 세우면(`slot` 재선언) 이모지도 사라진다.
- **인물의 페이드는 이모지와 무관하다.** `fade_out`은 계층 맨 아래의 초상 그림을 흐리게 하고, 이모지는 그 위(슬롯 계층)에 붙어 있다. 머무는 이모지를 치우려면 대본이 `emoji_off`로 끄거나 인물을 화면 밖으로 옮긴다. 원본도 같다(소유자 확인).

## 7. 단계

| 단계 | 무엇 | 확인 |
|---|---|---|
| 0 | 원본 GIF 실측(§1의 표) · §8 결정 | 아미야 |
| 1 | 기반 — `emoji` 리그 스키마 · 빌더 · 덤프 익스포트(`hasImage`) · 모션 로더의 리그 검증. 코드: `Stage/Emoji/EmojiRigDefinition.cs` · `EmojiRigBuilder.cs` · `Stage/Character/Motion/MotionRigSchemas.cs` | EditMode: 덤프 ↔ 실제 리그 등가. 덤프를 다시 내보내 모션 툴에서 `emoji` 리그가 열린다 |
| 2 | 기반 — 리그를 모르는 모션 재생기로 분리 + 반복 | 기존 캐릭터 모션 테스트 · 등가 하네스가 그대로 통과 |
| 3 | 이모지 정의 로더(`emojis.json`) · 이모지 자리(붙이기 · 등장 → loop → 퇴장 · 프레임 넘기기 · 페이드) · 커맨드 셋 · 파서 · 브리지 | 파서 테스트 |

## 8. 정할 것

| # | 물음 | 결정 |
|---|---|---|
| 1 | 이모지는 인물의 무엇을 따라가나 | **정함**: `CharacterRigSchema`의 슬롯 계층(`CharSlot_*`)은 따라가고 초상 계층(`CharacterPortrait_*`)은 무시한다 |
| 1b | 자리를 어디에 두나 — 이모지 리그가 뜰 때 값을 받는가, 캐릭터 리그에 **로케이터 노드**를 두고 거기에 붙이는가 | **정함**(2026-11-10): 로케이터 노드를 두지 않는다. 뜰 때 캐릭터의 소켓 표로 한 번 풀어 `Emoji_Anchor`에 놓는다(§3.2). 캐릭터 리그 스키마는 그대로다(§0). 소품이 같은 자리를 써야 하게 되면 그때 다시 본다 |
| 2 | 앞 인물에 가려져도 되나 | **정함**: 된다 — 인물 리그의 자식으로 그 인물의 층에 그린다 |
| 3 | 머무는 이모지는 인물이 사라질 때 함께 사라지나 | **정함**: 자동으로 묶지 않는다. 초상의 페이드는 이모지와 무관하다 — 대본이 끄거나 인물을 옮긴다(§6) |
| 4 | 불투명도 · 그림 교체를 모션 규약에 넣나 | **정함**: 넣지 않는다 — 이모지 정의의 값이다(§3.3) |
| 5 | 한 슬롯에 이모지 몇 개 | **정함**: 하나. 단 이모지 하나가 그림 여러 장(조각)을 쓴다(§3.1). **조각 수 N은 4 이상**(분홍 꽃이 넷) — 여유를 두어 **6으로 한다**(2026-11-10) |
| 6 | 좌우 반전(`mirror`)을 따라가나 | **정함**(2026-11-10): 따라가지 않는다. `mirror`는 초상 계층(`CharacterPortrait_ActingScale_X`)이라 1번에 따라 무시된다. 쪽은 대본의 인자(`left`/`right`)로만 정한다. 이모지가 떠 있는 동안 인물을 반전하는 연출은 쓰지 않는다 |
| 7 | 정의를 어디서 만드나 — 유니티 프리셋 DB인가, 모션 툴이 낸 파일인가 | **정함**(2026-11-10): 모션 툴이 `emojis.json`을 내고 런타임이 읽는다. 형식은 §4가 정한다 |
| 8 | 조각의 놓임을 어디에 두나 | **정함**(2026-11-10): 정의의 값이고 `Emoji_PartN_Image` 노드에 들어간다(§3.1). 모션의 키로 자리를 잡지 않는다 |

모션 툴이 먼저 만들어 둔 규약 가운데 이 문서와 다른 것(모션의 이벤트 키로 띄우기 · 모션의 불투명도 채널 · 캐릭터 방향으로 반전 판 고르기 · 정의의 필드 이름)은 툴이 이 문서에 맞춘다 — 툴의 `docs/PLAN-characterRig.md`.

## 9. 나중

- **감정 묶음** — 감정 하나가 표정 · 이모지 · 컷인 판 테마를 함께 부른다.
- 모션 툴의 **연출 클립**(`PLAN-clip.md`)에 이모지 배역 — 리그 덤프가 생기면 툴 쪽은 줄이 늘 뿐이다.
- 소품 — 같은 기반(§3.1 · §3.2)에 리그 종류와 소켓(손)을 더한다.
- 메신저의 이모티콘 말풍선 — 이 문서와 다른 물건이다(`PLAN_messenger.md` §8).
