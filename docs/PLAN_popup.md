## 목표 한 문장

> 그림 팝업은 **덮는 무대 하나의 팝업 그룹**이다. 그룹 아래 뒷막(세기 고정)과 그림이 있고, 움직이는 값은 그룹 불투명도 **하나**뿐이다.

## 1. 근거 — 원본 게임 GIF 둘

아미야가 원본 게임에서 녹화한 GIF 둘(1240×680, 약 70ms 간격) — 등장 하나, 퇴장 하나.

**자** — 그 장면의 원본 배경(`BG_uniseed_basement_night`, 2540×1800)을 GIF에 맞대면(일치도 0.988) 0.637 GIF px = 캔버스 1px이다(배경은 캔버스 픽셀 그대로 그려진다 — PLAN_background-source-pixels). 이 자로 팝업을 잰다.

**그림** — `story/elements/Story_element_qstory_main_06_003.png`(404×404, 일치도 0.96). 흰 테두리 · 둥근 모서리는 그림 파일 안에 있다(2px 투명 여백 + 약 7px 테두리).

| 잰 것 | 값 | 비고 |
|---|---|---|
| 크기 | 원본 픽셀의 **0.91배**(404 → 약 368px) | ±0.005 |
| 자리 | 화면 가운데 | 배경 가운데 기준 오차 0.3px. 배경이 기본 프레이밍이라는 전제 |
| 페이드 중 크기 · 자리 | 그대로 | 프레임마다 배율 0.90~1.10을 맞춰 모두 1.00 |
| 뒷막 | 거의 검정(약 10/255), 세기 0.47 | 채널별 0.44~0.49 |
| 뒷막 ↔ 그림 | 막의 진행 = 그림 불투명도, 프레임마다 같다 | 등장 · 퇴장 모두 — 한 페이드 |
| 대사창 | 팝업이 다 뜬 뒤 약 1.2초 지나 나타나고, 퇴장 전에 먼저 약 0.4초 동안 사라진다 | UI — 비교 밖(대본의 일) |

**등장 불투명도** (시각 0 = 마지막 0 프레임과 첫 변화 프레임의 가운데)

| +초 | 0 | 0.035 | 0.105 | 0.175 | 0.245 | 0.315 | 0.385 | 0.445 |
|---|---|---|---|---|---|---|---|---|
| 불투명도 | 0 | 0.07 | 0.42 | 0.53 | 0.75 | 0.93 | 0.97 | 1.00 |

**퇴장 불투명도** (시각 0 = 마지막 1 프레임과 첫 변화 프레임의 가운데)

| +초 | 0 | 0.035 | 0.095 | 0.165 | 0.235 | 0.305 |
|---|---|---|---|---|---|---|
| 불투명도 | 1.00 | 0.92 | 0.76 | 0.51 | 0.23 | 0 |

모르는 것: 시작 시각의 ±35ms, 점 사이의 곡선 모양(GIF 간격), 0.105 → 0.175의 느린 구간이 진짜인지 녹화 간격의 흔들림인지.

## 2. 계층 — 창의 다음 형제

```
StageViewportLayer (mount)
  stage00_Window → stage00_Stage_Root     본 무대
  stage00_Popup                           (선다. 본 무대에는 쓸 수 없다)
  stage01_Window → stage01_Stage_Root     덮는 무대 내용(카메라 중립)
  stage01_Popup                           ← 그룹(CanvasGroup) — 불투명도 하나
    stage01_Popup_Backdrop                ← 화면 전체, 색 · 세기 고정(프리셋)
    stage01_Popup_Image                   ← 그림, 원본 픽셀 × 0.91 × 대본 배율
  stage02_Window …
  stage02_Popup …
```

- **한 그룹** — 원본의 "막 = 불투명도 × 0.47"이 구조에서 나온다. 대본이 페이드 둘을 맞추는 것이 아니라 값이 하나뿐이다.
- **창 바깥** — 같은 무대에서 컷인이 팝해도 팝업은 끌려가지 않는다.
- **창 바로 다음** — 그 무대의 내용(같은 덮는 무대의 인물 포함) 위, 다음 무대 아래. 순서는 무대 인자로 고른다(컷인과 같은 규칙).
- **무대 루트 바깥** — 측정 체인 · 리그 덤프 · 하네스 · 샷 · `tx` 마스크와 무관하다.
- 세우기는 `StageFrameBuilder.EnsurePopup`(노드 이름도 빌더 안), 꺼내기는 `StageFrameRegistry.Popup`. 묶을 때마다 창 다음 자리로 돌리고 닫힌 중립으로 선다. 스키마에 없는 자식은 경고하고 치운다.

### 검토한 다른 안 (가) — 슬롯 두 개

막 슬롯과 그림 슬롯을 `slot · bg_sprite · fade_in`으로 풀어 내는 안. 그림은 배경 원본 픽셀 크기 방식을 그대로 쓸 수 있지만, 막의 47% 세기와 화면 전체 크기 방식이 새로 필요하고, 두 페이드가 같이 움직이는 것을 대본이 지켜야 한다. 측정이 말하는 "하나"를 구조로 갖지 못해 버렸다.

## 3. 어휘

```
<<popup {무대=stage01} {그림} {x=0u} {y=0u} {배율=1}>>
<<popup_close {무대=stage01}>>
```

- 그림은 `Resources/Popups/{키}`. x y는 그림 중심 — 무대 중심 기준 u(1u = 40px). 배율은 프리셋 배율에 곱한다.
- 본 무대(`stage00`)에는 쓸 수 없다 — 파서 · 런타임은 경고하고 건너뛰고, 폴드는 Unhandled.
- 열린 팝업에 다시 `popup`을 쓰면 불투명도 1에서 1로 — 그림 · 자리만 바로 바뀐다(원본에서 본 적 없는 경우, 번쩍이지 않게).
- 열지 않은 무대에 `popup_close`는 경고하고 건너뛴다(폴드는 Unhandled).
- 그림을 못 찾으면 해석기가 경고하고 뒷막만 뜬다(폴드는 열림).
- 원본에 두 장 동시 팝업은 없다(아미야). 무대마다 하나씩이라 구조상 둘이 될 수는 있지만 대본이 쓰지 않는다.

## 4. 값 — 프리셋 `PopupPresetDBSO`

Create › Ked › Presentation › Popup Preset. 없으면 코드 기본값(위 실측)으로 열고 경고한다(컷인 프리셋과 같은 규칙).

| 값 | 기본 | 근거 |
|---|---|---|
| `pictureScale` | 0.91 | §1 |
| `backdropColor` | (0.04, 0.04, 0.04, 0.47) | §1 — 알파가 그룹 불투명도 1일 때의 세기 |
| `openTimes` · `openAlpha` | §1 등장 표 | 0에서 1로 |
| `closeTimes` · `closeAlpha` | §1 퇴장 표 | 1에서 0으로 |

- 곡선은 잰 점을 지나는 매끈한 곡선(`PresetCurveKeys.Smooth` — 컷인 창 모션과 같은 함수, 이번에 둘이 같이 쓰도록 옮겼다). 0~1을 넘지 않는다(테스트).
- 규칙: 시각과 값의 개수가 같고 둘 이상, 첫 시각 0, 오름차순, 양끝 값이 페이드의 양끝. 어긋나면 커맨드는 경고하고 끝값만 쓴다.
- 커맨드는 곡선을 진행(0 → 1)으로 읽는다: 불투명도 = 시작값 + (끝값 − 시작값) × 진행.

## 5. 실행 — `PopupOpenCommand` · `PopupCloseCommand`

tx(`StageMaskMotionCommand` · `StageMaskSlot`)와 같은 틀이다 — 커맨드는 프리셋 · 그림을 골라 슬롯에 걸기만 하고, 페이드는 슬롯이 소유한다.

- 슬롯의 DOTween 하나가 그룹 불투명도를 몬다(`StagePopupSlot.PlayOpen` · `PlayClose`).
- 같은 팝업의 앞 페이드는 먼저 확정한다. tx · 마스크 지우기 · 장면 경계는 끝값 없이 끊고 닫는다(`Reset`).
- 압축 재생(스킵 · 되감기의 앞 줄들)에서는 끝 상태(열림 · 닫힘)로 바로 간다(`SnapOpen` · `SnapClose`).
- 스텝 경계는 페이드를 건드리지 않는다 — tx 모션처럼 제 끝까지 돈다.

## 6. 다른 커맨드와의 관계

| 커맨드 | 팝업에 |
|---|---|
| 장면 경계 | 모든 무대의 팝업을 닫는다(`StageFrameRegistry.ResetAll`) |
| 그 무대의 `tx` | 닫는다(열려 있었으면 경고) — 그 무대를 새로 보여 주는 전환이 덮는다 |
| `tx_stage_mask_clear` | 그 무대(또는 전부)의 팝업을 닫는다 |
| 컷인 | 무관 — 팝업은 창 밖이다 |
| 샷 | 무관 — 덮는 무대 카메라는 중립이고, 팝업은 무대 루트 밖이다 |

원본에서 장면이 넘어갈 때 팝업이 남는 경우는 보지 못했다.

## 7. 폴드 — 끝 상태만

`StageState.Popups` — 무대 키 → `PopupState { 열림, 그림 키, 자리, 배율 }`(컷인의 `CutInState`와 같은 모양). 페이드 도중은 접지 않는다.

폴드는 tx · 마스크 지우기가 팝업을 닫는 것을 모른다 — 폴드가 마스크를 모르는 것과 같은 경계(컷인과 같다).

## 8. 그림

- 원본 그림(`ked-originals/story/elements`, 420장 — 거의 404×404)은 공개 저장소에 넣지 않는다. 비공개 저장소(`ked-vn-workspace`)에 둔다.
- 공개 예제 그림 둘(`Samples/Content/Resources/Popups/sample_seedling` · `sample_letter`)은 원본 규격(404 정사각형 · 2px 투명 여백 · 밝은 테두리 · 둥근 모서리)에 맞춰 새로 그렸다. `.meta`는 스프라이트 설정으로 넣었다.

3. EditMode 테스트 — `PopupTests` · `StageCommandParserTests` · `StageRigBuilderTests` · `CutInTests` · 기존 전부.
4. (선택) Popup Preset 에셋을 만들어 `SampleBootstrap`의 Popup Preset 칸에 연결한다. 비우면 경고 한 줄.
5. 데모 대본의 그림 팝업 세 줄: 화면이 그림과 같이 어두워지는지, 그림이 가운데 368px인지, 다시 쓰면 그림만 바로 바뀌는지, 닫을 때 막과 그림이 같이 사라지는지, 스킵 · 되감기에서 끝 상태가 같은지.
6. 원본 GIF와 나란히 — 등장 약 0.45초 · 퇴장 약 0.3초, 크기 · 자리 그대로.
