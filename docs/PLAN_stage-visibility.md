# 무대에 무엇이 보이나 — 보이는 범위는 마스크 하나, 내용은 모두 리그, 틀은 창만 (2026-11-17)

> 상태: **끝났다** — V1–V5 구현, 소유자가 Unity에서 확인했다(2026-11-17, "대체로 잘 된다"). 정할 것(§6)은 모두 정했다.
> 런타임 밖(연출 카드 · 작업공간 · 툴)에 반영할 것은 [stage-changes-handoff.md](stage-changes-handoff.md)에 적었다.
> 이 계획이 [PLAN_stage-code-homes.md](PLAN_stage-code-homes.md)의 §3 · §8과 R2(틀 되돌리기)를 대신한다.
> **목표는 원본을 똑같이 재현하는 것이 아니라 연출 카드를 구현하는 것이다**(소유자, 2026-11-17). 원본 실측(색 · 곡선)은 맞추지 않는다.
> 본보기: 무대 리그([stage-rig.md](../Assets/Ked.Presentation/Stage/StageRig/Documentation~/stage-rig.md)) — 배경도 캐릭터 리그로 서고(캐스팅하지 않은 슬롯), 층마다 어둡기 판이 선다([PLAN_screen-cover.md](PLAN_screen-cover.md) §3.2).

## 1. 무엇이 꼬였나

소유자의 물음에서 시작했다 — `tx`가 왜 그 무대의 컷인 · 팝업을 닫나. 다 가리면 어차피 안 보이고, 닫히는 동작 전에 먼저 사라지면 어색하다.

```
{stage}_Window              틀 — 컷인이 팝 · 회전. 닫히면 배율 0으로 남는다
  {stage}_Panel             틀 — 컷인 판 그림(인물 뒤 배경). 마스크 밖
  {stage}_Stage_Root        무대 리그
    {stage}_Mask_Root       무대 리그 — 보이는 범위. tx · 마스크 지우기 · 컷인(네 점)이 쓴다
      층 · Content          배경 · 인물(리그)
{stage}_Popup               틀 — 뒷막 + 그림(Image 둘, 한 페이드). 창 밖, 마스크와 무관
```

1. **"이 무대가 보이나"를 두 곳이 정한다.** 마스크가 정하는데, 컷인은 닫을 때 창을 배율 0으로 남겨 무대를 통째로 숨긴다. 그래서 다음 `tx`는 창을 되돌려야 보였고, 되돌리기가 정상 순서에서도 경고했다.
2. **무대에 그려지는 것이 마스크 밖에 있다.** 컷인 판 그림과 팝업은 마스크 밖이라 `tx`로 가려지지 않는다. 그래서 `tx`가 그것들을 직접 꺼야 했고, 끄는 순간이 닫히는 동작보다 먼저라 어색했다.
3. **폴드와 화면이 어긋난다.** 폴드는 `tx`가 틀을 끄는 것을 모른다.

## 2. 정의

| 요소 | 정의 | 쓰는 쪽 |
|---|---|---|
| **마스크**(무대 리그) | 이 무대의 무엇이 보이나. **보이기 · 숨기기는 모두 여기 하나** | `tx` · 마스크 지우기 · 컷인. 나중에 쓴 것이 이긴다 |
| **층의 Content**(무대 리그) | 무대에 그려지는 것은 **모두 리그** — 배경 · 인물 · 컷인 판 · 팝업 그림 | 각 리그의 커맨드 |
| **층의 어둡기 판**(무대 리그) | 그 층까지와 아래 무대를 검게 덮는다 — 어둡게. 팝업 뒤를 까는 것도 대본이 이것으로 한다 | `screen_dim`만 |
| **창**(무대 틀) | 무대를 화면 위에 어떤 자세로 띄우나(팝 · 회전). **숨기는 일은 하지 않는다** | 컷인만 |
| **`tx`** | 마스크만 움직인다. 틀도 리그 내용도 모른다 | — |
| **장면 경계** | 마스크 · 판 · 창을 기준으로. 부르는 쪽(`ScenePresentation`)이 드러내 부른다 | — |

`tx`와 컷인은 "덮는 무대의 어디가 보이나"에서 같은 것이고(같은 마스크, 같은 모양 목록), "무엇이 움직이나"에서 다르다 — `tx`는 경계만, 컷인은 창이 통째로 튄다. 그래서 컷인 = 마스크 모양 + 창 모션이다.

**무대는 각자 독립된 화면이다**(소유자, 2026-11-17). 덮는 무대(stage01 · stage02)는 본 무대와 따로 자기 카메라(중립) · 층 · 마스크 · 창을 가진 전용 계층이고, 컷인 · 팝업 · `tx` 인서트는 그 화면을 보여 주는 방식이다. 컷인이나 팝업은 전용 무대를 하나 잡아 쓴다.
한 무대에 무엇을 함께 둘지는 대본의 선택이다 — 같이 두면 그 무대의 마스크 · 창을 함께 따르고, 겹치지 않게 자리를 잡으면 된다. 런타임은 막지도 고치지도 않는다.

## 3. 바뀌는 것

대본 어휘(`tx` · `tx_stage_mask_clear` · `cutin_open` · `cutin_close` · `popup` · `popup_close`)는 이름 · 인자 · 생략값이 **그대로**다. 바뀌는 것은 그 명령이 무엇으로 풀리고 어디에 쓰는가다.

### 3.1 `tx` · 마스크 지우기

| | 지금 | 바뀐 뒤 |
|---|---|---|
| `tx` | [틀 되돌리기, 마스크 모션] — 그 무대의 컷인 · 팝업을 먼저 끈다 | 마스크 모션 **하나** |
| `tx_stage_mask_clear` | [틀 전부 되돌리기, 마스크 전부 지우기] | 마스크 전부 지우기 하나 |
| 열린 컷인 위의 `tx` | 판이 먼저 꺼지고 창이 펴진 뒤 `tx`가 돈다 | 판 · 인물이 **함께** `tx` 모양대로 닫힌다(모두 마스크 안) |
| 열린 팝업 위의 `tx` | 팝업이 페이드 없이 꺼진다 | 그림이 그 무대 안이라 `tx` 모양대로 잘린다. 대본이 그 무대에 깐 어둡기 판도 같다 |

틀 되돌리기 커맨드(`StageFrameResetCommand`), 파서가 `tx`를 둘로 내던 일, 실험 토글(`txKeepsOpenFrames`)과 데모의 "tx와 열린 틀" 절은 걷는다.

### 3.2 컷인

```
<<cutin_open stage01 pink_stars -11.5u -3.25u [배율]>>
  → 판 리그 — stage01의 far 층에 배경과 같은 방식으로(그림 CutInPanels/pink_stars, 자리 x · y, 배율). 없으면 세운다
  → 창 — 피벗을 판 아래 가운데로, 마스크를 네 점으로, 팝 인
<<cutin_close stage01>>
  → 창 — 팝 아웃. 끝에서 창을 항등으로 돌리고 마스크를 숨김으로(배율 0으로 남기지 않는다)
```

- 판은 인물(mid · front)보다 뒤인 far 층에 선다. 자리 · 배율은 대본에 한 번만 적는다 — 파서가 판 리그와 창에 같은 값을 나눠 준다.
- 판 그림은 캔버스의 2배 해상도로 그려져 있다(`CutInPanelGenerator`). 원본 픽셀 크기 규칙으로 세우면 두 배가 되므로 리그 배율에 그 비를 곱한다.
- 판도 마스크 안에 들어오므로 **판 아래 외곽선**이 잘린다. 잘린 아래 외곽선은 **마스크 테두리 선으로 다시 그린다**(Q1 정함). 테두리(`MaskEdge_Root`)는 마스크의 형제라 잘리지 않고, 창 안이라 팝 · 회전을 같이 탄다.
  - 테두리가 네 점 모양의 **아래 변 중 판 너비만큼**(판 왼쪽 아래 → 오른쪽 아래)을 그리게 더한다 — 마스크의 아래 변은 화면 끝까지 이어지지만 외곽선은 판 밑에만 있다.
  - 두께 = `maskInsetPixels`(외곽선 두께), 색 = 판 그림의 외곽선 색. 생성기(`CutInPanelGenerator`)의 외곽선 색은 테마와 상관없이 하나라 프리셋에 그 색 하나를 둔다.
- 닫힌 뒤 판 리그는 남는다(Q2) — 마스크가 숨기고, 다음 `cutin_open`이 다시 세운다. 같은 무대를 `tx` 인서트로 쓰기 전에는 대본이 치운다: `<<bg_fade_out stage01_cutin_panel 0fr>>`.

### 3.3 팝업

```
<<popup stage02 sample_letter [x y 배율]>>
  → 그림 리그 — stage02의 close 층에(그림 Popups/sample_letter, 원본 픽셀 × 0.91 × 배율, 자리 x · y). 없으면 세운다. 페이드 인
<<popup_close stage02>>
  → 그림 리그 페이드 아웃
```

- **팝업은 그림 하나다. 뒷막과 세트가 아니다**(소유자, 2026-11-17). 뒤를 어둡게 까는 것은 그림을 강조하려는 연출이고, 필요하면 대본(연출 카드)이 `screen_dim`으로 깐다:
  ```
  <<screen_dim front 0.47 0.4s Linear stage02>>    그림(close 층) 바로 뒤의 판 — 그 무대의 far ~ front와 아래 무대를 덮는다
  <<popup stage02 sample_letter>>
  …
  <<popup_close stage02>>
  <<screen_dim front 0 0.3s Linear stage02>>
  ```
  `screen_dim all … stage02`는 close 층의 판이라 그림 앞이다 — 그림까지 어두워진다.
- 어둡기 판은 `screen_dim`만 쓴다. 팝업이 판에 쓰지 않으므로 "같은 판을 두 명령이 쓰는" 일이 없다.
- 열린 팝업에 다시 `popup` — 그림 · 자리만 바로 바뀐다(지금과 같다).
- 그림이 무대 안이라 그 무대의 마스크와 창을 따른다. 같은 무대에 컷인이 열려 있으면 팝업도 그 마스크에 잘리고 팝에 끌려가지만, 그것은 한 무대에 둘을 함께 둔 대본의 선택이다(§2 — 무대는 각자 독립된 화면). 생략 무대는 지금(stage01) 그대로 둔다.

### 3.4 무대 틀 — 창만

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 노드 | 창 · 판 · 팝업 그룹(뒷막 · 그림) | **창** 하나 |
| `StageFrameRegistry` | `CutIn` · `Popup` · `Reset` · `ResetAll` | `CutIn` · `Reset` · `ResetAll` |
| 팩토리 | 컷인 · 팝업 · 틀 되돌리기 | 컷인(창 · 마스크) |
| 프리셋 | `CutInPresetDBSO`(판 크기 · 모서리 · 마스크 · 모션), `PopupPresetDBSO`(배율 · 뒷막 색 · 곡선) | `CutInPresetDBSO`는 그대로(테두리 색을 더한다), `PopupPresetDBSO`는 그림 배율 · 페이드 길이만 — 뒷막 · 곡선은 걷는다. 값은 파서가 판 · 그림 리그로 푸는 데 쓴다 |

- 틀 노드는 씬에 저장되지 않는다(조립이 세운다) — 옮길 씬 데이터가 없다.
- stage-frame.md는 "창 — 무대를 화면 위에 띄우는 자세"로 줄어든다.

### 3.5 폴드 · 하네스 · 코어 사본 — 코어는 모른다

**컷인 판과 팝업 그림은 폴드 밖이다**(소유자, 2026-11-17). 코어 리듀서는 바뀌지 않는다.

- 폴드가 캐릭터 리그를 접고 하네스가 비교하는 까닭은, 인물의 자리 · 크기가 측정 체인 · 초점 · 깊이 · 샷 반응을 지나는 계산이고 그 계산이 런타임과 코어에 두 벌 있기 때문이다. 툴은 코어의 그 값으로 저작한다.
- 컷인 판과 팝업 그림의 자리 · 배율은 대본 인자 그대로다 — 맞춰 볼 계산이 없다. 툴이 미리보기에 쓸 것은 이미 끝 상태 표 `CutIns`(열림 · 판 · 자리 · 배율) · `Popups`(열림 · 그림 · 자리 · 배율)에 있다. 표는 그대로 둔다.
- 다만 하네스의 캡처(`StageStateCapture`)는 살아 있는 캐릭터 리그를 **전부** 읽는다. 판 · 그림을 배경처럼 캐릭터 리그로 세우면 캡처에 잡혀 "캡처에는 있는데 접힌 상태에 없다"가 뜬다. 그래서 **런타임 쪽에서** 이 리그를 "폴드 밖"으로 세워, 캡처가 건너뛰게 한다 — 리그를 세울 때 표시를 달고 레지스트리가 그 표시를 든다. 캡처는 표시를 보고 건너뛴다(이름이 아니라 등록으로).
- 마스크 · 어둡기 판 · 창과 같은 줄에 선다 — target-boundary.md의 "무대 상태 모델 밖"에 컷인 판 · 팝업 그림을 더한다.
- 레이어 블러(`screen_blur`)는 지금처럼 그 층의 리그를 모두 흐린다 — 판 · 그림도 흐려진다. 배경과 같다.
- 코어가 바뀌지 않으므로 툴의 코어 사본도 그대로다.

## 4. 재생 방식

새 커맨드가 없다 — 리그 페이드 · 마스크 모션 · 어둡기 판 · 창 모션이 이미 가진 규칙을 그대로 쓴다.

| | 동작 |
|---|---|
| 보통 재생 | 각 주인이 제 전환을 끝까지 돈다. 스텝 경계에 묶이지 않는다 |
| 압축(빨리 넘기기 · 스텝 서두르기 · 시크) | 모두 끝값으로 바로 |
| 되감기 | 정지(`StopAsync` — 마스크 · 어둡기 판 · 창을 기준으로) → 다시 준비(`PrepareReplay` — 리그를 치운다) → 루트부터 시크로 다시 세운다. 판 · 그림 리그도 인물처럼 다시 선다 |
| 장면 경계 | 정지와 같다 |

## 5. 하지 않는 것

- 명령 이름(`tx` → `stage_mask` 등) — 따로 정한다(PLAN_stage-code-homes.md §6).
- 블러의 집(PLAN_stage-code-homes.md §5).
- 판 그림까지 `tx` 모양과 다른 모양으로 닫는 연출 — 판이 마스크 안이라 필요 없어졌다.

## 7. 단계

판과 팝업을 무대 안으로 들인 뒤에 `tx`의 틀 되돌리기를 걷는다 — 중간에 마스크 밖에 남는 것이 없게. 단계마다 Core 테스트와 Stage · EditMode 컴파일을 지나고 커밋한다.

| 단계 | 일 | 확인 |
|---|---|---|
| V1 | 컷인 닫힘을 마스크로 — 팝 아웃 끝에 창 항등 · 마스크 숨김. 닫힌 창을 되돌릴 일이 없어져 정상 순서의 경고가 사라진다 | 슬롯 테스트(닫힌 뒤 창 항등 · 마스크 숨김), 압축 끝값 |
| V2 | 판을 리그로 — 파서가 `cutin_open`을 [판 리그(폴드 밖), 창]으로 푼다. 틀에서 판 노드를 걷는다. 마스크 테두리가 네 점의 아래 변(판 너비)을 그린다. 캡처가 폴드 밖 리그를 건너뛴다. Q2 | 파서 테스트(무엇을 어떤 순서로), 빌더 테스트(창 아래 판이 없다), 테두리 테스트(네 점의 아래 변), 캡처 테스트(폴드 밖 리그를 건너뛴다) |
| V3 | 팝업을 리그로 — 파서가 `popup` · `popup_close`를 그림 리그(폴드 밖)의 세우기 · 페이드로 푼다. 틀에서 팝업 그룹을 걷고, 프리셋에서 뒷막 · 곡선을 걷는다. 데모 대본의 팝업 절은 뒤를 `screen_dim`으로 깐다 | 파서 테스트, 빌더 테스트 |

| V5 | 문서 — stage-frame.md(창만) · stage-rig.md(Content · 판 · 마스크) · PLAN_cutin · PLAN_popup에 바뀐 것 · command-authoring §2 · §6 · target-boundary(모델 밖에 컷인 판 · 팝업 그림). 데모 대본의 컷인 · 팝업 절에 "열린 채 `tx`" 확인을 더한다 | |

**Unity에서 소유자가 볼 것**
- 컷인 열기 · 닫기가 전과 같은가 — 팝 인 · 팝 아웃, 판이 인물 뒤, 머리가 판 위로, 판 아래 외곽선(테두리 선으로 다시 그린 것)이 팝 · 회전 중에도 판에 붙어 있는가.
- 닫은 컷인 뒤 같은 무대의 `tx` 인서트가 보이는가, 경고가 없는가.
- 열린 컷인 위의 `tx` — 판과 인물이 함께 `tx` 모양으로 닫히는가.
- 팝업 열기 · 닫기 — 그림의 자리 · 크기 · 페이드. 데모 대본이 `screen_dim`으로 깐 뒤가 그림 뒤에서만 어두운가.
- 빨리 넘기기 · 시크 · 되감기에서 끝 상태가 같은가.
