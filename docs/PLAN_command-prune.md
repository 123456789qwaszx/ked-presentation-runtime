# 커맨드 걷기 — 종류 표를 두기 전에

2026-11-21 · 브랜치 `feat/command-prune`(dev에서) · 앞선 일: [PLAN_line-anchor.md](PLAN_line-anchor.md)

## 0. 한 문장

**커맨드는 한 노드를 인자에 적힌 값으로 놓는 것만 둔다.** 무대를 읽어 값을 푸는 것과 이름 하나가 여럿을 내는 것은
커맨드가 아니라 도구의 일(프리셋 · 보조 버튼)이다.

## 1. 왜

연출가는 한 줄의 명령을 종류별로 걸러 본다(카메라 / 자리와 구도 / 연기 / 화면). 그러려면 커맨드 하나가 종류 하나에 들어가야 하고,
적힌 값이 곧 결과여야 한다. 아래 두 가지는 그 표에 넣을 수 없다.

- **역산** — 결과가 인자에 없다. 실행하는 순간의 무대(초점 표 · 다른 노드의 끝값 · 카메라의 몸)를 읽어 값을 푼다.
  같은 줄을 두 자리에 쓰면 다른 값이 나오고, 연출가는 그 명령이 무엇을 얼마나 움직였는지 대본에서 읽을 수 없다.
- **묶음** — 이름 하나가 명령 여럿을 낸다. 한 줄이 여러 종류에 걸친다.

손으로 yarn을 쓸 때는 쓸모가 있었다. 도구가 값을 적어 주는 지금은 일관성을 해친다.

## 2. 정한 것 (소유자, 2026-11-21)

| # | 결정 |
|---|---|
| P1 | `show`를 걷는다 — 넷을 내는 묶음이고 쓰는 대본이 없다. 인물은 `cast` + `fade_in`으로 선다. |
| P2 | `shot_to`를 걷는다 — 줌과 팬은 `shot_zoom` · `shot_pan`을 나란히 적는다. `shot_to`는 둘을 함께 쓰면 뒤의 것이 무시되던 때에 넣은 것이고, 샷의 전환이 축마다 따로가 된 뒤(11-17, `08a156db`)로는 그 문제가 없다. |
| P3 | `size` · `size_reset`은 남기되 **초점 보존을 뗀다** — 프리셋의 배율과 Y를 그대로 놓는다. 보존에 필요한 보정은 도구가 자리 명령으로 적는다. |
| P4 | `place` · `place_left` · `place_center` · `place_right` · `shot_focus_to`를 걷는다 — 도구의 보조 버튼이 대신한다. 버튼은 지금 자리와 갈 자리를 재서 보통 명령(자리 · 크기 · 줌 · 팬)을 적는다. 계산은 코어에 순수 함수로 남는다. |
| P5 | `cast` · `cutin_open` · `popup` · `portrait`는 묶음이지만 둔다 — 연출이 아니라 **세우기**다. 역산이 없고 결과가 인자와 프리셋으로 정해지며 제 슬롯만 건드린다. 종류 표에서 "세우기" 한 덩어리로 본다. |
| P6 | 버튼(도구)이 생기기 전에 런타임에서 먼저 걷는다. 그 사이 데모 · 예제 대본의 값은 코어 함수로 풀어 적는다. |

## 3. 단계

| 단계 | 무엇 | 상태 |
|---|---|---|
| C1 | `show` 걷기 | 끝 — `a50034ea` |
| C2 | `shot_to` 걷기 | 끝 — `c6a8aa3d` |
| C3 | `size`에서 초점 보존 떼기 — 인자는 `size 슬롯 깊이 [길이] [이징]`. 데모 · 예제의 `size` 19곳에 보정 `move_by`를 풀어 적었다 | 끝 — 이 커밋 |
| C4 | `place` 계열 · `shot_focus_to` 걷기 — 데모 · 예제의 값을 풀어 적은 뒤 | |

**데모 · 예제의 값을 푸는 법(P6)**: 코어 위의 작은 변환기가 대본을 줄 차례로 접으면서, 옛 명령이 뜻하던 자리(그 초점이 그 화면 지점에 ·
크기가 바뀌어도 그 초점이 제자리에)를 `SettledFocusMath.SolveFocusPlacement`로 `CharSlot_Track`의 이동으로 푼다 — 보조 버튼이 할 일과 같다.
값은 0.001u로 맞춰 적고, 같은 때에 시작하는 한 슬롯의 `move_by`는 하나로 합친다(한 노드에 트윈 둘을 걸 수 없다).
확인은 두 겹이다: ① 고친 대본을 새 코어로 접은 것 = 변환기가 뜻한 무대, ② 옛 대본을 옛 코어로 접은 것 = 고친 대본을 새 코어로 접은 것
(대사 · 스텝마다 인물의 자리 · 배율 · 기울기). 코어 폴드는 좌우 반전(`mirror`)을 모르므로 ②는 반전을 끄고 맞대고,
반전된 인물의 줄은 런타임의 식(초점 오프셋 X를 뒤집는다)으로 따로 푼다.

단계마다 코어와 Unity를 쓰지 않는 시험(28개 파일)을 .NET 8 + NUnit으로 돌린다. 파서 · 브리지 · 실행 커맨드는 Unity 밖에서 컴파일하지 못한다 — 소유자가 본다.
