## 0. 이 문서를 읽는 법

- 이 문서는 정본이다. 관문별 세부 계획·체크리스트·진행 상태는 `docs/plans/G{n}.md`에 있다.
- 관문은 **순서대로** 진행한다. 한 관문의 완료 기준을 전부 통과하기 전에 다음으로 넘어가지 않는다.
- 각 관문은 독립적으로 컴파일·플레이 가능한 중간 지점이다. 커밋은 소유자가 직접 한다.
- "하지 않는 것"은 의도적 제외다. 필요해 보여도 추가하지 않는다.
- 검증 도구: `dotnet build Assembly-CSharp.csproj`(문법·타입) + Unity 수동 재생.

## 1. 배경 — 확정된 설계

- 수명 계층: **시나리오(회차) > Chapter > Scene(신설) > Episode**.
- Episode는 저작·실행 블록일 뿐, 연출적으로 투명하다. 아무것도 초기화하지 않는다.
- Scene이 네 경계를 전부 가진다: **연출 연속(무대·스코프) / 롤백 / 변수 체크포인트·선택 기록 / 커밋 확정·저장**.
- 한 문장: "장면 안에서는 모든 게 물릴 수 있고, 장면이 끝나면 확정된다."
- [2] 진행 스탯은 진행 코어만 안다. Yarn 투영(PublishStats) 철거, 대사 내 `<<if $스탯>>` 금지 —
  스탯 분기는 그래프 간선으로 올린다. Yarn 저장소 = 순수하게 [3]의 집.
- [3]은 Scene 종료 시 통덤프로 세이브에 들어간다 (G4에서 구현됨).
- 백로그는 회차 수명. 새 게임에서만 지운다.
- 무대 승계(Scene 시작 모드)는 범위 밖 — v1은 Scene 시작 = 무대 클리어 고정.

## 2. 수명 매트릭스 (목표 상태)

| 수명 | 소유 | 경계에서 |
|---|---|---|
| 회차 | 백로그, 플레이 시간 | 새 게임에서만 백로그 클리어 |
| Chapter | [2] 확정 상태, [3] 변수, 그래프·스탯 정의 | [3] 초기값 선언, [2] 진입 상태 생성 |
| Scene | 무대, PresentationScope, 롤백 포인트, 변수 체크포인트, 선택 기록, 미확정 커밋 | 진입: 체크포인트·무대 기준선 / 종료: 커밋 확정 + 저장 |
| Episode | 진행 커서, 시청 이벤트 보고 | 없음 |

## 3. 공통 완료 기준 (모든 관문에 적용)

## 7. 무대 복원 — 상황별 답 (2026-09-02 정리)

| 상황 | 방식 | 상태 |
|---|---|---|
| 장면 안 롤백 | 무대를 비우고 루트부터 **재실행**. 라인은 시크 패스스루, 커맨드는 그대로 실행(`CommandRunScope.IsSeekPassThrough`). 진행 선택지는 기록대로 자동 응답 | G2 완료 |
| 이어하기 | 장면 중간 재개 경로를 **없앰** — 세이브 = 장면 진입 스냅샷(루트 + [2]·[3]) 또는 챕터 완료. 루트 노드가 무대를 세우고, [3]은 덤프로 되살림 | G4 완료 |
| 장면 경계 무대 승계 | 장면 끝 `StageState`를 굽고(`StageReducer`·`StageStateCapture` — 있음) 다음 장면 시작에 되살림(**없음**). 유일하게 남은 "접기" 작업 | 후속 (§5) |

로드에 재실행(Load 시크)을 붙이는 안은 장면 안 선택 경로·Yarn 인라인 선택을 세이브에 실어야 하고
콘텐츠 변경에 취약해 기각 — [3]을 덤프로 되살리는 결정과 같은 이유다.
