## 1. 왜 시작했나

`EpisodePlayer`는 테스트용 노드 실행기로 출발했는데, 기능이 붙으며 장면 경계·롤백 경계·변수
체크포인트·선택 기록·백로그·무대 수명·스코프·Stop/Replay 동기화까지 전부 떠안았다. 그 결과
**에피소드(= Yarn 노드) 진입마다 초기화 묶음이 터졌다** — 무대 클리어, 체크포인트 재캡처, 선택 기록
리셋. `ContinueEpisodeAsync`라는 이름과 달리 실제로는 "새 독립 장면을 시작"하고 있었고, 그래서
승계 문제를 계속 보정해야 했다.

작가는 "교실 이야기 + 복도 이야기 + 수업 이야기"를 한 흐름으로 엮는다. 그런데 런타임은 그 사이를
세 번 끊었다. 구체적으로 드러난 증상:
- 에피소드가 바뀌면 캐릭터·배경이 사라진다(연출 단절).
- 진행 선택지를 지나면 롤백이 그 앞으로 못 간다(커밋이 즉시라 물릴 수 없음).
- 장면 둘째 에피소드에서 종료하면 세이브가 거기를 가리켜, 재개 시 캐스팅 없이 대사만 나온다
  (소유자 발견, G3 중).

한 줄 진단: **Episode는 저작 단위이며, 런타임 장면 경계를 의미하지 않는다.** 네 경계(연출 연속 /
롤백 / 체크포인트·선택 기록 / 커밋·저장)를 새 개념 하나에 모으고, 에피소드는 연출적으로 투명하게 만든다.

## 2. 확정된 설계

- 수명 계층: **시나리오(회차) > Chapter > Scene(신설) > Episode**.
- 한 문장: "장면 안에서는 모든 게 물릴 수 있고, 장면이 끝나면 확정된다."
- [2] 진행 스탯은 진행 코어만 안다. Yarn 투영(`PublishStats`) 철거, 대사 내 `<<if $스탯>>` 금지.
  스탯 분기는 그래프 간선으로. Yarn 저장소 = 순수하게 [3]의 집.
- 장면은 런타임이 정의하지 않고 받는다(`Nodes[].SceneId`, 생략 가능). 비면 에피소드 하나가
  장면 하나 = **퇴화 상태** = 장면 개념 전과 동일 동작. 전 관문의 회귀 방어선.
- 장면 불변식은 하나: 밖에서 들어오는 자리(루트)가 하나. 재진입(허브)은 허용.
- 롤백 = 장면 루트부터 재실행. 커밋 = 장면 끝 fold. 세이브 = 장면 진입 스냅샷 또는 챕터 완료.
- 백로그는 회차 수명. 무대 승계(장면 시작 모드)는 범위 밖 — v1은 장면 시작 = 무대 클리어.

| 수명 | 소유 | 경계에서 |
|---|---|---|
| 회차 | 백로그, 플레이 시간 | 새 게임에서만 백로그 클리어 |
| Chapter | [2] 확정 상태, [3] 변수, 그래프·스탯 정의 | [3] declare 초기값, [2] 진입 상태 |
| Scene | 무대, PresentationScope, 롤백 포인트, 변수 체크포인트, 선택 기록, 미확정 선택 | 진입: 무대 기준선·체크포인트 / 종료: fold + 저장 1회 |
| Episode | 진행 커서, 시청 기록 | 없음 |

## 3. 진행 방식

- 관문 순서대로, 관문 하나가 독립적으로 컴파일·플레이 가능한 중간 지점. 각 관문 안에서도
  "기전을 먼저 잠든 채로 들여오고 경계는 마지막에 한 줄로 뒤집는" 순서를 지켰다.
- 검증: `dotnet build Assembly-CSharp.csproj`(3초, 타입 오류) → `Ked.Progression`은 엔진 참조가
  없어 콘솔 프로젝트로 실제 실행 검증 → Unity 수동 재생 → 소유자 검토·커밋.
- 공통 완료 기준: 빌드 통과 / 퇴화 상태에서 기존 시나리오(`qwer`)가 현행과 같다 / 범위 밖을
  건드리지 않았다.

## 4. 관문별 작업 내역

### G0. [2]↔Yarn 읽기 연동 철거

**근거.** [2]의 쓰기는 이미 간선 커밋뿐이었고, Yarn 연동은 읽기(`PublishStats`로 투영 → 대사가
`<<if $호감도>>`)뿐이었다. 소유자 결정: 대사에서 스탯 표현·분기 금지. 진행 그래프가 볼 수 없는
숨은 [2] 분기가 대사 속에 있는 것 자체가 도달성 증명의 사각이었고, 금지가 증명을 온전하게 한다.
Yarn 저장소에 [2] 투영이 없어야 뒤의 체크포인트·[3] 덤프가 필터링 없이 통째로 간다.

**한 일.** `ProgressionYarnBridge.PublishStats`·`NameOf` 삭제. `ProgressionDriver.SyncYarnVariables` →
`SyncChapterVariables`(BeginChapter만). `ProgressionContentPreflight`의 스탯/declare 타입 대조
(`VerifyStatTypes`, `Mismatched`) 삭제. 테스트 yarn의 `$int`/`$power` 읽기 3곳 정리 — EP01은 항상
참이던 조건 해체, EP02_01은 빈 블록 삭제, EP02_02는 [3] 변수(`능력이바뀌`) 분기로 대체해 "챕터 수명
[3]이 에피소드를 넘는다"의 살아 있는 테스트로 전환.

**확인된 사실.** 콘텐츠의 스탯 읽기 3곳 중 실제 분기는 1곳뿐이었다. preflight는 이제 "부르는 노드가
실재하는가"만 본다.

### G1. Scene 소속 데이터

**근거.** 런타임은 장면을 정의하지 않고 받아야 툴(Exporter)이 늦어도 막히지 않는다. 기본 발급을
로더가 아니라 `EpisodeNode` 생성자에 두어, 어떤 생성 경로로도 `SceneId`가 비는 노드가 없게 했다.

**한 일.** `EpisodeNodeDto.SceneId`, `EpisodeNode.SceneId`(비면 `"__scene_" + EpisodeId`),
`ChapterProgression.IsSameScene / SceneIdOf`, `ChapterInvariants.VerifySceneEntries`.
`Ked.Progression`에 테스트 어셈블리 신설(`Tests/EditMode`, `SceneBoundaryTests`).

**결정 — 재진입 금지를 철회.** 초안은 불변식 둘(연결성 + 재진입 금지)이었다. 구현하며 재진입 금지가
"장면을 넘는 순환 전부 금지"와 같다는 것이 드러났다 — 모든 에피소드가 어떤 장면엔 속하므로. 그러면
허브 구조(교실 ↔ 복도)를 만들 수 없어 표현력이 후퇴한다. 근거로 삼았던 "진입 묶음은 한 번"이라는
가정도 사실이 아니었다(런타임은 "직전과 같은 장면인가"로 매번 판단하므로 재진입은 새 장면 방문일 뿐).
그래서 **진입점 하나만** 강제한다. 밖에서 오는 길이 루트뿐이면 도달 가능한 에피소드는 전부 루트에서
내부 간선으로 이어지므로 연결성은 따라오고, 고아 노드를 오류로 잡지도 않는다(이 클래스는 구조적
무결성만 본다는 기존 태도 유지).

**확인된 사실.** 퇴화 상태는 이 규칙을 구조적으로 위반할 수 없다(장면마다 착지점이 자기 자신 하나).
`Ked.Progression`은 Unity 밖 콘솔에서 컴파일·실행된다 — 이후 코어 검증에 계속 썼다.

### G2. SceneScope 추출

**근거 — 순서를 뒤집었다.** 초안(루프 분리 → 경계 이동 → Via → 기록 → 리플레이)은 중간 지점이
위험했다. 경계를 먼저 올리면 리플레이는 노드 하나만 되감는데 무대는 비워져, 다중 에피소드 콘텐츠에서
롤백 한 번에 앞 에피소드의 캐릭터·배경이 사라지는 상태를 검증 대상으로 노출한다. 그래서
**리플레이 기전을 먼저 전부 세우되 퇴화 상태에서는 잠들어 있게 만들고, 마지막에 경계 한 줄만
뒤집었다.** 독해로 확인한 전제: 시크 좌표(노드명·라인ID·장면 내 등장 순번)는 이미 노드를 넘어
세는 구조라 다중 노드 리플레이와 호환되고, 프레젠터는 노드 완료 시 무대를 안 건드리므로
`PresentationStage.Clear`만 안 부르면 연속성이 성립하며, 노드 사이에서 `StopDialogueAsync`를
부르면 롤백 포인트 클리어가 시크 좌표계를 중간에 리셋하므로 금지.

**한 일.**
- G2-1 (동작 불변): `EpisodePlayer`를 `EnterSceneAsync` / `PlayNodeAsync`(결과 반환) /
  `PrepareReplayAsync`로 분해. 리플레이 루프를 드라이버로. 디버그 경로(`RunYarn`, `RunEpisodeChain`)용
  `StartGameAsync`/`ContinueEpisodeAsync`는 얇은 래퍼로.
- G2-2 (잠든 기전): `SceneRunner` 신설 — 장면 루프, 진행 선택 기록(간선·앵커·커밋여부), 시크 활성
  시에만 자동 응답, 롤백 하한(`RollbackHistory` floor — 커밋 앞 거부, 잠정), 시청 보고 1회 집합.
  드라이버는 챕터 루프·상태·챕터 변수만. 장면 끝 판단 `!IsSameScene`과 Via의 장면 안 재생도 이때
  넣었다 — 퇴화 상태에서는 발동할 수 없으므로.
- G2-3 (경계 전환 = 테스트 콘텐츠): `qwer_scene.progression.json`(장면 2개, Via 2개) +
  `test/qwer_scene.yarn`(노드 이름 `SC_*`로 분리해 퇴화 기준선 보존, 대사에 `[사무실 7]` 식 번호).
- G2-4: 진행 선택지 박스가 떠 있을 때의 롤백 — `EpisodePlayer.ReplayRequestedWhileIdle` 이벤트로
  박스를 접고, `ShowAsync`의 취소 예외를 `IsReplayPending` 필터로 리플레이로 읽는다.

**규칙 — 자동 응답은 시크가 살아 있을 때만.** 표적 라인에 닿아 시크가 꺼졌으면 선택지는 사람이 다시
고른다(Yarn 옵션 흐름과 같은 규칙). 그래서 "선택 직전 라인으로 돌아갔는데 선택이 자동으로 지나가는"
일이 없고, Via 안 롤백(미커밋 기록 → 자동 응답 → Via 패스스루 → Via 끝에 커밋 1회)도 맞게 처리된다.

**확인된 사실.** 다중 노드 리플레이가 실물로 동작. 롤백 하한은 커밋 직후 첫 라인에서 한 걸음도 못
돌아가는 벽으로 실제 작동했다 — G3이 없앨 위치를 정확히 짚었다. 소유자가 "장면 중간 에피소드에서
종료 → 재개 시 빈 무대" 버그를 발견 — 저장 지점과 장면 경계가 어긋난 것이 원인, G3→G4로 구조적으로
닫기로.

### G3. 커밋 유예

**근거.** G2가 절반을 이미 했다(기록·앵커·자동 응답). 남은 것은 커밋을 언제 적용하는가(즉시 → 장면 끝)와
하한 제거. 작업 상태는 `진입 상태.FoldChoices(pending)`로 언제든 재계산되는 파생물이라, 롤백은 상태를
되돌리는 코드가 아니라 입력을 자르는 코드다. fold가 `ApplyChoice`의 합성이라 검증 규칙이 갈릴 수 없다.
장면 중간 멈춤의 pending은 확정도 보고도 하지 않는다 — "장면 중간 종료 = 장면 처음부터".

**한 일.** `ProgressionState.FoldChoices` + `ProgressionStateFoldTests`(5건). `SceneRunner`: 즉시 커밋
삭제, 판정은 작업 상태로, 자동 응답은 커서만 전진, 장면 끝(SceneEnded·ChapterEnded)에서 fold →
보고, 시청 기록도 앵커를 달아 롤백 시 함께 물림. 롤백 하한(floor API·피처 컨트롤러 거부 분기·
`Committed` 깃발) 삭제.

**확인된 사실.** 장면을 나가는 fold의 확정 위치는 다음 장면 루트라 세이브가 장면 중간을 가리키는
경로가 이 단계로 대부분 사라졌다. 남은 구멍은 챕터 끝 fold(마지막 장면이 여럿이면 위치가 루트가 아님)
— G4로 넘김.

### G4. 저장 정렬 + [3] 덤프

**근거.** 세이브의 뜻을 한 문장으로: **장면 진입 스냅샷(루트 + 그 시점 [2]·[3]) 또는 챕터 완료.**
이 둘만 있으면 재개 지점이 장면 중간일 수 있는 경로가 데이터 정의에서 사라진다. G3 덕에 fold의
확정 상태가 곧 다음 장면의 진입 스냅샷이라 저장할 것이 이미 손에 있다. 챕터 끝은 다음 장면이 없으니
스냅샷이 아니라 완료 표시. 보고도 장면 1회로 접는다(G3은 선택 N개를 따로 보고해 로컬 저장이 N번).
복원은 `BeginChapter`(declare 초기값) 위에 덤프를 **덮는다** — 덤프에 없는 신규 declare는 초기값으로
남아, [2] `Restore`가 저장 후 추가된 스탯을 다루는 것과 같은 문장.

**한 일.** `ChapterProgression.IsSceneRoot`, `YarnVariableSnapshot`(floats·strings·bools),
`ProgressionYarnBridge.Capture/Restore`. `IProgressionReporter.ReportSceneCommitted(SceneCommitReport)`
하나로(옛 `ChoiceCommitReport`·`EpisodeWatchReport` 삭제). `SaveCoordinator`: 로컬 저장 1회 → 큐
적재(Seq 순서) → 동기화. `LocalSaveFile`에 `Variables`·`ChapterCompleted`. 런처 세 갈래: 챕터 완료 →
새 게임 / 위치가 루트 아님(구형식) → 경고 후 새 게임 / 복원. 드라이버는 첫 `BeginChapter` 뒤 덤프 덮기.
서버 스냅샷은 파일 통째라 서버 변경 없음.

**확인된 사실.** 둘째 에피소드에서 종료 → 재실행이 장면 루트부터 무대가 선 채로 시작하고 앞 장면의
`<<set>>`이 덤프로 살아온다 — 소유자 발견 버그 종결.

### G5. 백로그·롤백 UX 경계

**근거·확인.** `ClearBacklog` 호출처는 `EpisodePlayer.EnterSceneAsync`의 새 게임 분기 하나뿐 — 회차
수명 확정. 이전 장면 점프 차단은 차단할 대상이 없었다: 백로그 패널은 읽기 전용이고, 롤백은 한 걸음뿐
인데 롤백 포인트가 장면 진입에서 비워지므로 새 장면 첫 라인에서는 `CanRollbackOneStep=false`. 초안의
"항목마다 Scene 태그" 계획은 불필요해 철회. 코드 변경 없음.

### G6. 자동 간선 (후속 계획에서 앞당김)

**근거.** 장면 안 에피소드 경계는 곧 진행 간선이고 간선은 선택지 박스로 나타나니, "에피소드는 나누되
물을 게 없다"는 자리가 반드시 생긴다(블루아카이브가 뜻 없는 두 선택지를 늘 붙이는 것도 같은 구조적
압력의 흔적). 개수로 추론하지 않고 **명시적 깃발**로 둔다 — 옛 자동 진행(문구 없는 간선)이 툴의 실수를
조용히 지나가게 했던 함정, 그리고 런타임 암묵적 결정 제거 원칙.

**규칙 넷(로드에서 검사).** 그 에피소드의 유일한 간선 · 조건 없음 · 스탯 변화 없음(스탯 효과는
플레이어에게 보이는 선택지에서만 — 도달성 증명과 UX의 근거) · 같은 장면(장면 경계는 무대가 갈리는
자리라 모르게 넘어가면 이상하다).

**함께 되살린 것.** 리팩터 커밋 `8ba99014`에서 빠졌던 "고른 간선이 지금 에피소드에서 나가는 길인가"
검증을 `ProgressionState.RequireOutgoingEdge`로 복구(소유자 결정). 그래프에 없는 경로로의 이동을 막는
마지막 관문이고, `순서가_어긋난_간선은_거부된다` 테스트가 그것을 지킨다.

**한 일.** `EpisodeOptionDto.Auto` → `EpisodeOption.IsAuto`(팩토리 `Auto`). 로더는 Auto일 때만 빈
문구 허용. `ChapterInvariants.VerifyAuto`. `ChapterAdvanceKind.AutoAdvance` — `Resolve`가 유일한
자동 간선이면 판정 없이 반환. `SceneRunner`는 AutoAdvance면 박스를 건너뛰고 기록에 바로 적는다 —
리플레이·pending·fold는 보통 선택과 동일. 테스트 `AutoEdgeTests`(7건). 테스트 콘텐츠의 EP03→EP04를
자동 간선으로. 툴 UX("여기서 에피소드 나누기"가 자동 간선을 끼운다)는 후속.
