# 화면 덮기 · 어둡게 — 목표와 작업 계획 (2026-11-17)

상태: **계획 — 정할 것(§7)을 정한 뒤 S1부터.** 코드는 고치지 않았다.
근거: ked-vn-workspace 참고집의 화면 카드 일곱 장(암전 B01~B03 · 어둡게 D01~D04)과 그 쓰임(원본 14편), 이 저장소의 화면 효과 리그(`Stage/ScreenEffect`) · 리그 블러(`RigBlurIntentSystem`).

## 0. 목표

> 대본에서 **화면을 덮었다 걷는 일**과 **무대를 어둡게 하는 일**을 명령으로 바로 쓰게 한다 — 장면 머리에 검은 배경 슬롯을 세워 두고 그 투명도를 바꾸는 흉내 없이.

화면에서 일어나야 할 일:

| | 요구 |
|---|---|
| **A. 덮기 · 걷기** | A1 화면 전체(배경 · 인물 · 컷인 · 팝업)를 한 색으로 덮는다. 대사창 · HUD는 덮지 않는다 — 검은 화면 위에 글이 뜬다 |
| | A2 색은 검정이 기본, 흰색도(회상) |
| | A3 덮는 데 · 걷는 데 걸리는 시간을 대본이 정한다 |
| | A4 덮기와 걷기는 따로다 — 사이에 무대를 바꾸거나 대사가 지나간다 |
| | A5 무대를 바꾸는 일은 다 덮인 뒤에 일어난다 |
| | A6 카메라가 움직여도 덮개는 움직이지 않는다 |
| **B. 어둡게** | B1 무대 전체(배경 + 인물)를 어둡게 — 속말 · 회상 |
| | B2 배경만 어둡게(인물은 밝게) — 인물을 띄우는 자리 |
| | B3 켜기와 끄기는 따로다 — 몇 줄 이어진다 |
| | B4 어두운 동안 들어온 인물 · 바뀐 배경도 함께 어둡다 |
| **C. 둘 다** | C1 보통 재생 · 빨리 넘기기 · 클릭으로 서두르기 · 되감기 · 이어하기 어느 길로 그 줄에 와도 화면이 같다 |
| | C2 장면이 끝나면 원래대로 |

## 2. 기존 구조와 자리

### 2.1 그리는 차례

```
[StageCanvas]  Screen Space Overlay · 정렬 0          (PresentationSample 씬)
└ PresentataionUIRoot
  ├ StageViewportLayer    조립 때 무대 셋 — stage00/01/02의 창(무대 리그) · 팝업
  └ ScreenEffectLayer
     └ ScreenEffectRig    조립 때 스키마대로(SampleBootstrap.EnsureScreenEffectRig)
        └ ScreenOverlay_Root
           ├ Cover_Image      ← 새로 — 덮개
           ├ Vignette_Image
           ├ Noise_Image
           └ Flash_Image
[KedUICanvas]  Screen Space Overlay · 정렬 20         PlayScreen — 대사창 · HUD · 자막 · 메뉴
```

- 두 캔버스는 정렬 순서로 겹친다. `ScreenEffectRig` 안의 것은 무대 셋을 모두 덮고, HUD · 대사창 · 자막(정렬 20)은 덮지 않는다 — A1 · A6이 이 자리에서 저절로 선다.
- 덮개는 무대를 가리는 뚜껑이라 화면 효과의 맨 아래, 비네트 · 노이즈 · 플래시는 보이는 화면에 얹는 렌즈라 그 위다(→ 정할 것 D2). 검은 채 흰 화면이 터지는 자리(작업공간 프롤로그)가 이 차례를 요구한다.

### 2.2 화면 효과 리그의 꼴

스키마(`ScreenEffectRigSchema` — 노드 표, 표의 차례 = 그리는 차례) → 빌더(세우고 다시 묶음) → 리그(`ScreenEffectRig` — 창구 · 0으로 되돌리기) → 그림마다 컨트롤러 하나(`IScreenEffectController`) → 머티리얼(`UIEffectMaterialBinding`). 설정은 프리셋 DB, 대본은 이름 × 세기. 커맨드는 목표를 셈해 컨트롤러에 넘길 뿐 트윈을 들지 않는다. 코어는 접지 않는다(포스트 이펙트 축 — `target-boundary.md`).

컨트롤러는 두 꼴이다 — **의도형**(비네트 · 노이즈: 머무는 상태, `IntentTransition`, 압축이면 끝값) · **이벤트형**(플래시: 터지고 0으로).

### 2.3 셋 다 의도형이고, 범위가 자리를 정한다

덮기 · 걷기 · 어둡게는 모두 머무는 상태를 절대값으로 말한다 — 의도형이다. 덮기 · 걷기는 상태 하나(덮인 정도 · 색)를 두 방향으로 쓰는 명령 둘이다(비네트와 그 `_clear`처럼). 이벤트형(플래시처럼 한 번에)으로는 쓸 수 없다 — 머무는 길이를 미리 적어야 하고(검은 화면 위 대사 6곳이 안 된다), 덮인 동안의 무대 정리를 그 사이에 끼울 수 없다.

| 범위 | 따라가는 쪽(이미 있는 길) | 이번 일 |
|---|---|---|
| 화면 전체 | `ScreenEffectRig`의 컨트롤러 | 덮기 · 걷기 |
| 무대 · 층 | 시스템이 `(무대, 층)` 의도를 들고 리그마다 `RigVisualEffectController`로 내려 줌 — 줄 머리마다 다시 맞춤(`StepHead` → `RigBlurIntentSystem.Reconcile`), 처음 보는 리그는 Snap, 압축이면 Snap, 정지에서 비움 (`screen_blur`) | 어둡게 — 무대 전체(층 전부) · 배경만(배경이 선 층) |
| 슬롯 하나 | `RigVisualEffectController`(`char_visual_*`) | 이번에 두지 않는다 |

## 3. 만들 것

### 3.1 덮기 · 걷기 — `ScreenEffectRig`

```yarn
<<screen_cover [프리셋=black] [길이=0.5s] [이징]>>
<<screen_cover_clear [길이=0.5s] [이징]>>
```

- **프리셋**은 색이다(`ScreenCoverPresetDBSO` — `black` · `white`). 같은 식구(`screen_flash` · `screen_vignette`)처럼 대본은 이름, 값은 DB.
- `screen_cover`는 **다 덮일 때까지 기다린다** — 뒤 명령(무대 정리)은 늘 덮인 밑에서 일어난다(A5). 의도형 커맨드의 기다림(`wait`)을 늘 켠 것이고, 전환은 여전히 컨트롤러가 갖는다. 기다리는 동안 매 프레임 압축을 보아, 켜지면 끝값으로 가고 놓는다.
- `screen_cover_clear`는 기다리지 않는다 — 다음 줄이 열려도 제 길이로 걷힌다.
- 절대값이다 — 두 번 덮어도, 덮지 않고 걷어도 쌓이지 않는다.
- 덮기는 전경이라 인라인 `[cmd]`에는 쓸 수 없다(경고하고 버린다). 줄 머리 · 무대 스텝에 둔다.

손대는 곳:

| 파일 | 일 |
|---|---|
| `Stage/ScreenEffect/ScreenEffectRigDefinition.cs` | `Refs.Cover_Image` · 노드 표 맨 앞 · `ControllerKind.Cover` · 참조 칸 |
| `ScreenEffectRigBuilder.cs` · `ScreenEffectRig.cs` | 컨트롤러 붙이기 · 참조 묶기 · 창구 · 트윈 끊기 · 0으로 되돌리기에 덮개 |
| `ScreenCoverEffectController.cs`(새) | 의도형 — 상태(색 · 세기), `IntentTransition`, `Follow` · `Snap` · `ClearImmediate`. 그림은 단색이라 전용 셰이더가 없다 |
| `ScreenCoverPresetDBSO.cs`(새) · `Stage/Presets/ScreenCoverPresetDB.asset`(새) | `black` · `white` |
| `Commands/ScreenCoverCommand.cs`(새) · `ScreenEffectCommandFactory.cs` | 스펙 · 커맨드 둘 · 팩토리 |
| `Grammar/StageCommandParser.ScreenEffects.cs` · `.Table.cs` · `Playback/YarnBridge/CommandBridge*.cs` | 문법 · Yarn 등록 |

### 3.2 어둡게 — 층 의도(`screen_blur`의 짝)

```yarn
<<screen_dim <층|all> <세기> [무대=stage00] [길이=0.3s] [이징]>>
<<screen_dim_reset [길이=0.3s]>>
```

- 인자 차례는 `screen_blur`(층 · 세기 · 무대)와 같다. `all`은 그 무대의 층 전부(D01 · D02), `far`는 배경이 선 먼 층(D04 · D03 — `bg_spawn`의 기본 층이 `far`). 세기 0이 그 층을 걷기, `screen_dim_reset`은 전부 걷기.
- 의도는 시스템이 `(무대, 층)`마다 들고, 그 층 아래 리그 전부의 `RigVisualEffectController`에 어둡기를 내려 준다. 줄 머리마다 다시 맞추므로 뒤에 들어온 인물 · 바뀐 배경 · `size`로 층이 바뀐 인물이 따라간다(B4). 카메라와 상관없다.
- 기다리지 않고 줄을 넘는다. 압축이면 끝값, 정지에서 비운다.
- 리그의 어둡기는 리그 블러와 같은 꼴의 채널 하나(`IntentTransition<float>`)다. 그리는 길은 S0에서 정한다 — 그림의 정점 색으로 곱해지면 그것을, 아니면 셰이더(`SG_UICharacterVisual`)에 밝기 값을 하나 더한다.

한계(받아들인다):
- **이모지는 어두워지지 않는다** — 이모지 리그에는 시각 컨트롤러가 없다. 속말 중의 이모지는 드물다.
- **배경이 인물과 같은 층에 서면 "배경만"을 층으로 가를 수 없다** — 배경은 `far`에 세운다(런타임의 기본). 작업공간 대본은 지금 모두 `mid`라 들일 때 고친다.

손대는 곳:

| 파일 | 일 |
|---|---|
| `Stage/Character/Visual/RigVisualEffectController.cs` | 어둡기 채널(`Follow` · `Snap` · `Accelerate`) |
| `Stage/ScreenEffect/RigBlurIntentSystem.cs` | 층 의도에 어둡기(→ D5) |
| `Commands/StageLayerDimCommand.cs`(새) · 팩토리 · 문법 · 등록 | 커맨드 둘 |
| (S0 결과에 따라) `Resources/VisualEffects/SG_UICharacterVisual.shadergraph` | 밝기 값 |

### 3.3 재생 방식마다

압축(`PresentationSessionContext.CompressExecution`)은 빨리 넘기기 · 스텝 서두르기 · 시크에서 켜진다. 빠르게(속도 올림)는 압축이 아니다.

| 방식 | 일어나는 일 | 지킬 것 |
|---|---|---|
| 보통 · 자동 · 빠르게 | 덮기는 다 덮일 때까지 뒤 명령을 늦추고, 걷기 · 어둡게는 제 길이로 줄을 넘는다 | 전환은 컨트롤러 · 시스템이 갖는다(스텝 수명에 묶지 않음) |
| 빨리 넘기기 | 커맨드가 `OnSkip`으로 끝값에 바로 간다 | 덮개의 `OnSkip`은 끝값을 세운다(플래시처럼 끊으면 넘긴 뒤 덮개가 빠진다). 덮는 도중에 켜져도 기다림이 놓인다 |
| 클릭(스텝 서두르기) | 그 스텝에 압축 — 무대 스텝이면 바로 다 덮이고 뒤는 끝값. 글이 나오는 줄이면 첫 클릭은 글만 서두른다 | 위와 같다 |
| 되감기 · 이어하기 · 갈라지기 | 정지(화면 효과 0 · 리그 블러 비움) → 루트부터 압축 시크 | 덮개는 `ResetToBaselineImmediate`, 어둡기는 시스템의 `Clear`에. 표적 줄이 덮인 구간 안이면 시크가 다시 세운다 |
| 정지 · 장면 끝 | 위의 0 되돌리기 | 〃 |

### 3.4 실수할 자리

| 실수 | 지금의 흉내 | 이 계획 |
|---|---|---|
| 덮는 길이와 뒤 `pause`를 맞춰야 한다 | 그렇다 | 덮기가 다 덮일 때까지 기다린다 |
| 걷기 직후 줄이 바뀌면 툭 끊긴다 | 그렇다 | 줄을 넘는다 |
| 덮개 뒤에 세운 슬롯이 덮개 위에 선다 · 컷인이 안 덮인다 · 카메라에 가장자리 | 그렇다 | 없다 — 덮개는 무대 밖 |
| 걷기 · 끄기를 잊는다 | 그렇다 | 막지 못한다 — 장면 끝에서 0, 화면에 바로 보인다 |
| 대사 도중(인라인)에 덮는다 | — | 경고하고 버린다 |

## 4. 테스트 대본

데모 대본(`Assets/Dialogue/ChapterProgression/presentation_demo_Demo_Presentation.yarn`)에 절 둘을 더한다 — 카메라 · 이모지 절과 같은 자리. 예제 씬(`PresentationSample`)에서 그 대본을 재생하면 된다.

| 절 | 해 보는 것 | 눈으로 볼 것 |
|---|---|---|
| 덮기 · 걷기 | ① 짧게 끊기(덮기 0.3초 → 구도 바꿈 → 걷기, 한 스텝) ② 장소 옮기기(배경 · 사람 바꿈, 검게 0.4초 머묾) ③ 검은 화면 위 대사 두 줄 → 걷기 ④ 흰 화면으로 회상에 들어가고 나오기 ⑤ 덮인 채 컷인을 연 뒤 걷기 | 바뀌는 과정이 안 보이는가 · HUD · 대사창이 남는가 · 컷인도 덮이는가 · 줌 · 롤 · 흔들림 중에도 덮개가 그대로인가 |
| 어둡게 | ① 속말 두 줄(`all`) ② 판정 한 줄(배경만 — `far`) ③ 어두운 동안 인물 등장 · 배경 바꿈 ④ 컷인을 연 채 본 무대 배경만 ⑤ 회상(흰 덮기 + `all 0.2`) | 들어온 인물도 어두운가 · 컷인 창은 밝은가 · 줄이 바뀌어도 끊기지 않는가 |

두 절 모두 Ctrl(빨리 넘기기) · 클릭 · R(되감기)로 한 번씩 지나가 본다 — 끝 화면이 보통 재생과 같아야 한다.

## 6. 하지 않는 것

| 무엇 | 까닭 |
|---|---|
| 코어 폴드 | 화면 효과 · 머티리얼 축은 무대 상태 모델 밖이다. 접는다면 비네트 · 노이즈 · 블러까지 화면 효과 전체로 따로 정할 일이다 |
| 모양 있는 암전(아이리스 · 셔터 — `tx` 프리셋을 덮개에) | 카드가 없다(원본은 투명도 암전만). 이것이 서고 나서 |
| 덮기 줄임말(덮기 → 머묾 → 걷기를 한 명령으로) | 기본 둘로 다 쓸 수 있다. 써 보고 정한다 |
| 슬롯 하나만 어둡게 | 층으로 다 된다. 필요하면 `char_visual` 프리셋에 "그냥 어둡게"를 더한다(지금 `dim` 프리셋의 밝기 · 채도는 코드 상수) |
| 배경 디졸브 · 속말이면 저절로 어둡게 | 카드가 없다 · 속말이라는 줄 종류가 공개 런타임에 없다 |
| 원본의 밝기 곡선(작업공간의 0.2초 토막) | 목표는 의도와 전환이다(11-17 소유자) |
| 작업공간 대본 · 카드에 반영 | 이것이 확인된 뒤 작업공간에서(들이기 · `script.py` · 카드) |

## 7. 정할 것 (S1 전에)
