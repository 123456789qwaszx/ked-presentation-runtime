# 화면 덮기 · 무대 어둡게 — 계획 (2026-11-17)

상태: **계획 — 소유자 결정(§8)을 기다린다.** 코드는 고치지 않았다.
근거: ked-vn-workspace 참고집의 화면 카드 일곱 장(B01~B03 · D01~D04 — 모두 5단계 화면 확인을 거쳤다), 그 카드가 지금 기대는 꼼수, 이 저장소의 화면 효과 리그(`Stage/ScreenEffect`) · 무대 리그(`Stage/StageRig`).

## 0. 한 문장

> 화면을 덮었다 걷는 일(암전)과 무대를 어둡게 하는 일을 **이름 있는 명령**으로 쓰게 한다 — 장면 머리에 검은 배경 슬롯을 세워 두고 그 투명도를 바꾸는 흉내 없이.

참고집 카드의 "커맨드" 칸은 새 작품에서 AI가 쓸 명령이다. 속말 · 장면 전환 · 회상의 암전과 어둡게는 어느 비주얼 노벨에나 있는 의도인데, 지금은 그 의도를 쓰려면 슬롯을 세우는 법부터 알아야 한다.

## 1. 지금

| 카드 | 지금 커맨드 | 실제로 하는 일 |
|---|---|---|
| B01 장소 바꾸기(암전) | `fade bg_top 1 0.58s` → `pause` → `bg_sprite bg_main <배경>` → `pause` → `fade bg_top 0 0.52s` | 화면을 검게 덮고, 덮인 동안 무대를 바꾸고, 걷는다 |
| B02 시간 건너뛰기(암전) | `fade bg_top 1 0.37s` → `pause 0.64s` → `fade bg_top 0 0.4s` | 같은 장면에서 시간만 건너뛴다 |
| B03 장제목 · 장소 카드(암전) | `fade bg_top 1 0.77s` → (글 카드) → `fade bg_top 0 0.78s` | 검은 화면 위에 글 카드 |
| D01 속말 어둡게 | `fade bg_dim 0.73 0.27s` … `fade bg_dim 0 0.23s` | 배경과 인물을 함께 어둡게 |
| D02 회상 · 설명 살짝 어둡게 | `fade bg_dim 0.2 0fr` | D01을 약하게 |
| D03 어두운 바탕에 자막 | `fade bg_main 0.19 0fr` | 배경만 — 검은 슬롯 위에서 배경을 투명하게 |
| D04 배경만 어둡게 | `fade bg_main 0.3 0.3s` | 배경만 |

이것을 쓰려면 장면 머리에 슬롯 셋을 세워 두어야 한다.

```yarn
<<bg_spawn bg_black bg_black stage00 mid>>   // 맨 아래 검정 — 배경을 투명하게 하면 이것이 비친다(D03 · D04)
<<bg_spawn bg_main  <배경>   stage00 mid>>
// … 인물 슬롯 …
<<bg_spawn bg_dim   bg_black stage00 mid>>   // 인물 위 덮개(D01 · D02) — 같은 층이라 나중에 세운 것이 위다
<<bg_spawn bg_top   bg_black stage00 mid>>   // 맨 위 덮개(B01~B03)
```

### 1.1 흉내인 까닭

| # | 문제 |
|---|---|
| P1 | 카드를 쓰려면 슬롯 셋(`bg_black` · `bg_dim` · `bg_top`)과 그 세우는 차례를 알아야 한다. 덮개 뒤에 세운 슬롯은 덮개 위에 선다 — 층 안의 차례에 기댄다 |
| P2 | 덮개가 `stage00` 안에 있다. 뒤에 그리는 무대(`stage01` · `stage02` — 컷인 · 옆 판 · 그림 팝업)는 덮이지 않는다 |
| P3 | 덮개가 `mid` 층이라 카메라를 탄다 — 줌 · 팬 · 롤 · 흔들림에 덮개가 같이 움직이고, 넓히거나 기울이면 가장자리가 드러날 수 있다 |
| P4 | "배경만 어둡게"가 배경 슬롯의 투명도다. 아래 검정이 있어야 어두워지고, 배경의 등장 · 퇴장(`bg_fade_in/out`)과 같은 축이라 서로 덮어쓴다 |
| P5 | 이름이 의도를 말하지 않는다 — `fade bg_top 1`은 "덮는다"가 아니라 "슬롯을 보인다"다 |

**지켜야 할 좋은 점 하나:** 배경 슬롯은 코어가 접는다. 그래서 흉내라도 폴드 · 등가 하네스 · 저작 도구 미리보기가 "지금 화면이 검다"를 안다. 새 명령이 이것을 잃으면 흉내보다 후퇴다(→ Q2).

### 1.2 이미 있는 것

| | 어디 | 이번 일과의 관계 |
|---|---|---|
| `screen_flash` | 화면 효과 리그의 `Flash_Image`(프리셋: 색 · 세기 · 오름 · 머묾 · 걷힘) | 한 번 터지고 0으로 돌아온다 — 끝 상태가 없다. 흰 화면 카드(W01 · W02)가 쓴다. 암전은 줄을 넘어 머무르므로 이것으로 쓸 수 없다 |
| `screen_vignette` · `screen_noise` · `screen_blur` | 화면 효과 리그 | 폴드 밖(포스트 이펙트 축, `Core/Documentation~/target-boundary.md`) |
| `char_visual_dim` | 인물 리그의 머티리얼(밝기 0.62 · 채도 0.7 · 푸른 색조) | 듣는 사람을 물러나 보이게 하는 **양식화된** 어둡게다. 단순히 어둡게(D03 · D04)와 다르다 |
| `tx <프리셋> <무대>` | 무대 마스크 움직임(`slant` · `hstrip` · `vstrip` · `band` · `iris` · `shutter` · `daze` · `strip` 스무 개) | 덮는 무대를 모양으로 드러내고 감춘다 — 모양 있는 암전(§5)의 재료 |

자리: 무대 캔버스 안에서 `StageViewportLayer`(무대 셋) 위에 `ScreenEffectLayer`(화면 효과 리그)가 있고, 대사창 · UI는 그 위의 다른 캔버스다. 그래서 화면 효과 리그에 둔 것은 **무대 셋과 무대 틀을 모두 덮고 대사창은 덮지 않는다** — 암전 위에 글 카드(B03)를 띄우는 데 맞다. 화면 효과는 조립 때와 장면 경계에서 0으로 돌아간다(`ScreenEffectRig.ResetToBaselineImmediate`).

## 2. 새 명령 (제안)

| 명령 | 인자 | 하는 일 | 카드 |
|---|---|---|---|
| `screen_cover` | `[색=black] [세기=1] [0.5s] [이징]` | 화면 전체(무대 셋 · 무대 틀)를 그 색으로 덮는다. 대사창은 위에 남는다 | B01 · B02 · B03 |
| `screen_uncover` | `[0.5s] [이징]` | 덮개를 걷는다(세기 0) | 〃 |
| `stage_dim` | `세기 [0.3s] [이징] [무대=stage00]` | 그 무대를 — 배경 · 인물 · 이모지를 함께 — 어둡게 한다. 0이면 걷는다 | D01 · D02 |
| `bg_dim` | `슬롯 세기 [0.3s] [이징]` | 그 배경 슬롯만 어둡게 한다(색을 곱한다). 0이면 걷는다 | D03 · D04 |

- **세기**는 셋 다 "얼마나 덮었나"다 — 0은 그대로, 1은 다 덮음(검정). `stage_dim 0.73`은 검정을 73% 얹은 것, `bg_dim 0.7`은 배경을 30% 밝기로.
- **색**은 `black` · `white` · `#RRGGBB`. 흰 화면에서 장면을 여는 것(회상)은 `screen_cover white`로 덮었다가 걷는다. 한 번 번쩍이는 것은 지금처럼 `screen_flash`다.
- 전환의 규칙은 다른 트윈과 같다 — 다음 스텝이 열리면 가속해 끝나고(×30), 빨리 넘기기 · 시크에서는 끝값으로 간다(`OnSkip`).
- 덮개는 **카메라를 타지 않는다**(화면 효과 리그 · 무대 마스크 바로 아래에 선다 — §3).

카드는 이렇게 된다.

```yarn
// B01 장소 바꾸기
<<screen_cover black 1 0.58s>>
<<pause 0.58s>>
<<bg_sprite bg_main <배경>>>
<<pause 0.42s>>
<<screen_uncover 0.52s>>
<<step>>

// D01 속말
<<stage_dim 0.73 0.27s>>
(속말 줄들)
<<stage_dim 0 0.23s>>

// D04 배경만 어둡게
<<bg_dim bg_main 0.7 0.3s>>
```

장면 머리에 덮개 슬롯을 세우지 않는다. 배경 슬롯 `bg_main` 하나와 인물만 세운다.

## 3. 어디에 서는가

| 명령 | 노드 | 까닭 |
|---|---|---|
| `screen_cover` | 화면 효과 리그에 `Cover_Image` — `ScreenOverlay_Root`의 맨 아래(덮개 → 비네트 → 노이즈 → 플래시) | 무대 셋과 무대 틀을 모두 덮는다. 플래시는 덮개 위에 선다 — 검은 채 흰 화면으로 장면을 여는 자리(작업공간 프롤로그)가 그렇다 |
| `stage_dim` | 무대 리그에 `Dim_Image` — 무대마다, `Mask_Root`의 마지막 아이(카메라 리그 위) | 그 무대만 어둡게. 마스크에 잘리므로 컷인 무대면 창 안만. 카메라 위라 줌 · 팬 · 롤에 움직이지 않는다 |
| `bg_dim` | 배경 슬롯의 그림 색(정점 색 곱) | 그 슬롯만. 머티리얼(`char_visual_*`)과 축이 겹치지 않는다 — 캐릭터 비주얼 셰이더 그래프(`SG_UICharacterVisual`)에 정점 색 노드가 있다. 그것이 결과에 곱해지는지는 S3에서 Unity로 확인한다(곱해지지 않으면 머티리얼에 밝기 값을 하나 더한다) |

무대 리그 · 화면 효과 리그의 노드는 스키마가 정한다. 스키마가 바뀌므로 `ExportedTuning/rig-schemas.json`과 스키마 트리 테스트(`RigSchemaTreeUnityParityTests`)를 같이 고친다.

## 4. 폴드 · 하네스 · 사본

- 셋 다 **끝 상태가 있는 축**이다 — 줄을 넘어 머무른다. 그래서 코어가 접는 것을 제안한다(→ Q2): `StageState`에 화면 덮개(색 · 세기), 무대마다 어둡기, 슬롯마다 어둡기.
- 되감기 = 루트 세우기 + 루트부터 시크다(`PLAN_playback-unit.md` E2). 시크는 명령을 압축 실행하므로 접지 않아도 되감기는 맞는다. 접는 까닭은 **등가 하네스와 저작 도구**다 — 정지 프레임이 "지금 화면이 검다"를 알아야 하고, 지금의 흉내(배경 슬롯 투명도)는 그것을 안다.
- 등가 하네스의 스냅샷에 셋을 더한다(Unity 쪽은 노드의 세기를 읽는다).
- 코어가 바뀌므로 사본(ked-motion-tool-characterRig · ked-story-compositor · ked-vn-workspace)이 따라온다. 흐름은 한 방향이다 — 여기서 먼저 정한다.
- 장면 경계 · 조립 때 화면 효과와 함께 0으로 돌아간다(`ResetToBaselineImmediate`).

## 5. 모양 있는 암전 (트랜지션)

암전을 모양으로 — 원이 좁아지며 닫히고(아이리스), 셔터 · 띠 · 사선으로 덮었다 걷는다. 재료는 이미 있다: `tx`의 마스크 움직임 프리셋 스무 개.

```yarn
<<screen_cover black 1 0.6s iris_out>>   // 원이 닫히며 검게
<<bg_sprite bg_main <배경>>>
<<screen_uncover 0.6s iris_in>>          // 원이 열리며 걷힌다
```

- 덮개에 무대 마스크와 같은 마스크 그래픽(`StageMaskGraphic`)을 달고, 프리셋의 움직임을 덮개에 건다. 프리셋 DB는 그대로 쓴다.
- 모양이 없으면 지금처럼 투명도로 덮는다(§2).
- 참고집에는 이 카드가 아직 없다(원본은 투명도 암전만 쓴다). 그래서 **1~4를 먼저 하고 이것은 다음**으로 두기를 제안한다(→ Q6).

## 6. 단계

| # | 일 | 확인 |
|---|---|---|
| S1 | 코어 — 상태 셋, 리듀서(`screen_cover` · `screen_uncover` · `stage_dim` · `bg_dim`), 스냅샷 비교. 순수 테스트 | 유니티 밖 Core 테스트 |
| S2 | 화면 효과 리그 — `Cover_Image` · 덮개 컨트롤러 · 명령 둘 · 파서 · 브리지 등록 · 장면 경계에서 0 | 소유자 Unity |
| S3 | 무대 리그 — `Dim_Image` · `stage_dim`, 배경 슬롯 색 · `bg_dim`. 스키마 덤프 · 스키마 트리 테스트 | 소유자 Unity |
| S4 | 등가 하네스 — Unity 쪽 스냅샷이 셋을 읽는다. 데모 대본에 한 대목(암전 · 속말 · 배경만) | 소유자 Unity — 데모 재생 · 하네스 리포트 |
| S5 | 문서 — `command-authoring.md` · 이 계획의 진행 | — |
| S6 | (Q6) 모양 있는 암전 | 소유자 Unity |

S1이 끝나야 S2~S4가 접히는 값을 안다. S2와 S3은 서로 기대지 않는다. 한 단계마다 커밋한다.

## 7. 하지 않는 것

| 무엇 | 까닭 |
|---|---|
| 원본의 밝기 곡선 흉내(작업공간의 0.2초 토막 — 선형 공간에서 화면 밝기를 직선으로) | 목표는 의도와 전환이다(11-17 소유자). 이징으로 충분하다 |
| `char_visual_dim`을 바꾸기 | 듣는 사람 물러나기는 그대로 쓸모가 있다. 단순히 어둡게는 `bg_dim` · `stage_dim`이 맡는다 |
| 배경 디졸브(배경 그림끼리 겹쳐 바꾸기) | 카드가 없다. 지금은 덮개 밑에서 바꾸거나(B01) 바로 바꾼다 |
| 대사창까지 덮기 | 대사창은 UI 캔버스다. 대사 없는 암전은 `<<step>>`이 대사창을 닫는다 |

## 8. 정할 것

| # | 물음 | 제안 | 다른 길 |
|---|---|---|---|
| Q1 | 이름 | `screen_cover` · `screen_uncover` · `stage_dim` · `bg_dim` — 화면 효과는 `screen_`, 어둡게는 `_dim`(`char_visual_dim`과 같은 말) | `screen_fade_out` · `screen_fade_in`(인물의 `fade_in/out`과 헷갈린다) / `curtain` |
| Q2 | 코어가 접는가 | **접는다** — 끝 상태가 있고, 지금의 흉내도 접힌다(§4). 사본이 따라온다 | 화면 효과처럼 밖에 둔다 — 코어는 그대로지만 하네스 · 도구 미리보기가 암전을 모른다 |
| Q3 | 덮개의 색 | 검정이 기본, `white` · `#RRGGBB`도 | 검정만 — 흰 화면은 플래시로 |
| Q4 | `stage_dim`의 범위 | 무대마다(기본 `stage00`) — 속말에 컷인 창까지 어둡게 할지는 대본이 정한다 | 화면 전체 하나 — 컷인 · 팝업까지 늘 함께 어둡다 |
| Q5 | 배경만 어둡게 | `bg_dim` — 슬롯의 색을 곱한다 | `char_visual_dim`을 배경에 — 양식화된 어둡게라 의도와 다르다 / 지금처럼 배경 투명도 — 아래 검정이 있어야 한다 |
| Q6 | 모양 있는 암전(§5) | S1~S5 다음 | 이번에 함께 |
