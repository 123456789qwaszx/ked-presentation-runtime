## 0. 한 문장

> 이모지가 **어느 캐릭터의 어느 포즈에서도 제 머리 곁에**(결정 1), **맞는 쪽에**(결정 2) 뜨게 하고, **그림만 다른 이모지**를 어떻게 다룰지(결정 3) 정한다.

셋의 순서는 1 → 2 → 3이다. 2는 1이 세우는 "자리를 푸는 곳"에 얹히고, 3은 2가 반전 판을 풀고 나면 남는 것만 다룬다.

## 1. 지금 서 있는 것 (`007d4c16` 기준)

| | 지금 | 모자란 것 |
|---|---|---|
| 로케이터의 자리 | `SetEmojiCommand`가 세울 때 `emojiDefaultRootSpace`(조립 루트의 칸, 발에서 (0, 800)) 하나를 넣는다 | 키가 다른 캐릭터 · 앉은 포즈에서 머리와 어긋난다 |

| 좌우 | 이모지의 `offset.x`가 적힌 그대로(견본: `star` +170 · `question` −170). 인물이 뒤집혀도 그대로다 | 인물이 왼쪽을 볼 때 · 화면 가장자리에 설 때의 쪽 |
| 그림 묶음 | 리그가 스프라이트를 직접 든다. 같은 움직임에 다른 그림은 이모지를 따로 만든다 | 묶어 두는 길이 없다 |

## 2. 결정 1 — 캐릭터 + 바리에이션별 자리

**끝나면**: 캐릭터와 포즈가 달라도 이모지가 그 머리 곁에 뜬다. 값이 없는 캐릭터는 지금처럼 기본값에 뜬다.

### 정할 것

| | 무엇 | 제안 | 까닭 · 다른 길 |
|---|---|---|---|
| 1-1 | 값의 집 | **전용 표** `EmojiLocatorTuningDBSO`(ScriptableObject) — 조립 루트에 잇고, 덤프는 `ExportedTuning/presets/emoji-locator.json` | 캐릭터별 표 둘(`role-anchor` · `focus-tuning`)과 같은 모양이라 재는 법 · 덤프 · 읽는 법을 새로 배우지 않는다. **다른 길**: 얼굴 포커스 점(`focus-tuning`의 Face)에서 계산해 내는 것 — 잴 것이 없어지지만, 카메라가 보는 점과 이모지가 뜨는 점이 한 값에 묶여 한쪽을 고치면 다른 쪽이 움직인다. [emoji-rig.md](emoji-rig.md) §3.1이 "로케이터가 그 값을 대신한다"고 적은 것과도 어긋난다 |
| 1-2 | 키와 찾는 순서 | `캐릭터/포즈` → `캐릭터` → 기본값(`emojiDefaultRootSpace`) | 포즈마다 잴 필요가 없다 — 선 포즈가 여럿이면 캐릭터 값 하나로 덮고, 앉은 포즈처럼 머리가 내려간 것만 따로 적는다. 대소문자는 가리지 않는다(다른 표와 같다) |
| 1-3 | 값의 모양 | 발(`CharSlot_Scale`의 아래 가운데)에서 잰 px 하나(x, y) | 지금 기본값과 같은 단위다. 배율은 두지 않는다 — 깊이와 슬롯 배율은 이미 위에서 곱해진다. 캐릭터마다 이모지 크기를 달리할 일이 생기면 그때 칸을 더한다 |
| 1-4 | 머무는 동안 포즈가 바뀌면 | **로케이터가 따라 옮긴다**(그 자리에서 바로) | 따라가지 않으면 앉은 뒤에 별이 허공에 남는다. 캐릭터 쪽 코드가 이모지에 알리지 않는다 — 이모지 쪽이 매 틱에 `CastRegistry`를 읽어 키가 달라졌으면 다시 푼다(장부가 "지금 그 슬롯 밑에 선 것"만 남기는 것과 같은 방식) |
| 1-5 | 누가 재는가 | 소유자가 Unity에서 잰다. **재는 도구를 둔다** — 재생 중 로케이터를 끌어 옮기고 "이 캐릭터/포즈로 적기"를 누르면 표에 들어간다 | 캐릭터 수 × 포즈 수만큼 숫자를 손으로 맞추는 일이라 도구가 없으면 표가 비어 있게 된다. 도구는 뒤로 미룰 수 있다(1-D) |
| 1-6 | 툴이 이 표를 읽는가 | 지금은 읽지 않는다 | 툴은 이모지를 캐릭터 없이 만든다(이모지는 캐릭터를 모른다). 툴에서 캐릭터 위에 얹어 보는 미리보기를 원하면 그때 덤프를 읽힌다 |

### 작업 (정한 뒤)

| | 작업 | 끝나면 |
|---|---|---|
| 1-A | `Stage/Emoji/EmojiLocatorTuningDBSO.cs` — 항목(키 · 자리)과 찾기(1-2의 순서). `EmojiLocatorResolver` — 슬롯에서 `character` · `variant`를 읽어 자리를 낸다. `emojiDefaultRootSpace`는 마지막 기본값으로 남는다 | 자리를 푸는 곳이 하나다 |
| 1-B | `SetEmojiCommand`가 기본값 대신 리졸버를 쓴다. `EmojiPlaybackSystem.Tick`(또는 장부)이 슬롯마다 키가 바뀌었는지 보고 로케이터를 다시 놓는다(1-4) | 포즈가 바뀌면 따라간다 |
| 1-C | 덤프 — `PresentationTuningExporter`가 `presets/emoji-locator.json`을 낸다. `ExportedTuning/schema.md`에 적는다 | 표가 저장소 밖에서 읽힌다 |
| 1-D | 재는 도구(에디터) — 1-5 | 표를 채울 수 있다 |
| 1-E | 테스트(EditMode) — 찾는 순서 · 없는 캐릭터는 기본값 · 포즈를 바꾸면 로케이터가 옮겨진다 · 건너뛰기와 되감기에서 같은 자리 | 테스트 통과 |
| 1-F | 문서 — [emoji-rig.md](emoji-rig.md) §5 · §8의 5를 닫는다 | |

**하지 않는 것**: `CharacterRigSchema`와 캐릭터 커맨드를 고치는 것. 코어의 접기를 넓히는 것(접힌 상태는 이모지의 이름만 든다 — 자리는 무대에서 다시 풀린다).

## 3. 결정 2 — 좌우

**끝나면**: 인물이 어느 쪽을 보든 이모지가 맞는 쪽에 뜨고, 뒤집히면 안 되는 그림(물음표 · 글자)은 뒤집히지 않는다.

### 무엇을 묻는가

"좌우"에는 물음이 셋 섞여 있다.

1. **기준** — 이모지의 "오른쪽"이 화면의 오른쪽인가, 인물이 보는 쪽인가.
2. **무엇이 뒤집히는가** — 자리만인가, 그림까지인가.
3. **누가 고르는가** — 이모지인가, 인물의 방향인가, 대본인가.

### 정할 것

| | 무엇 | 제안 | 까닭 · 다른 길 |
|---|---|---|---|
| 2-1 | 기준 | **이모지는 "오른쪽을 보는 인물"을 기준으로 만든다.** 인물이 왼쪽을 보면 이모지 전체를 거울에 비춘다 | 땀방울은 뒤통수 쪽, 화난 표시는 이마 쪽처럼 이모지의 쪽은 대개 얼굴의 방향에 달려 있다. 인물의 기본 방향이 오른쪽이다(`SetupCharRigCommand`). **다른 길**: 화면 기준으로 고정(지금) — 인물이 뒤집히면 땀방울이 얼굴 앞에 온다 |
| 2-2 | 어디서 뒤집는가 | **`Emoji_Locator`에서**(가로 배율 −1, 자리의 x도 뒤집는다) | 경계(`Emoji_Offset`) 위라서 이모지의 값과 키는 하나도 바뀌지 않는다 — "이모지는 캐릭터를 모른다"가 그대로다. 오프셋 · 리그의 기본 자리 · x 키 · 회전이 한 번에 뒤집힌다 |
| 2-3 | 뒤집히면 안 되는 그림 | **리그마다 표시 하나**(`rigs[].upright: true`) — 그 리그는 `EmojiRig_Place`에서 가로 배율을 한 번 더 뒤집어 그림이 바로 선다(자리는 거울 쪽으로 간다) | 물음표 · 느낌표 · 글자는 읽히는 그림이다. 표시는 "이 그림은 한쪽으로만 읽힌다"는 그림의 성질이라 이모지가 가져도 캐릭터를 아는 것이 아니다. 형식에 더하는 칸이라 지금 파일을 깨지 않는다 |
| 2-4 | 방향을 따르지 않는 이모지 | **이모지에 표시 하나**(`side: "fixed"`, 기본은 방향을 따른다) | 머리 위 한가운데 뜨는 것 · 화면 기준으로 흐르는 것은 뒤집을 까닭이 없다. 좌우 대칭인 이모지는 표시가 없어도 같다 |
| 2-5 | 대본이 고르는가 | **지금은 두지 않는다** | `<<emoji s1 star left>>` 같은 셋째 칸은 2-1로 안 풀리는 장면(화면 가장자리에 선 인물)이 실제로 나오면 얹는다. 얹어도 지금 대본을 깨지 않는다 |
| 2-6 | 머무는 동안 인물이 뒤집히면 | **세울 때의 쪽을 지킨다** | 머무는 이모지가 갑자기 반대쪽으로 튀는 것보다 낫다. 포즈(1-4)와 다르게 두는 까닭 — 포즈가 바뀌면 자리가 틀려지지만, 방향이 바뀌어도 이모지는 여전히 머리 곁에 있다. **다른 길**: 따라 뒤집는다 — 1-4와 규칙이 하나가 된다 |

### 작업 (정한 뒤)

| | 작업 | 끝나면 |
|---|---|---|
| 2-A | [emoji-rig.md](emoji-rig.md) §3.1 · §8의 6과 [emoji-format.md](emoji-format.md)에 정한 것을 적는다(`upright` · `side`) | 정의와 형식이 먼저 선다 |
| 2-B | 코어 — `EmojisFileDto` · `EmojiDefinition` · 로더 · `EmojiRules`에 두 칸. 순수 테스트 | 툴과 런타임이 같은 것을 읽는다 |
| 2-C | Stage — 리졸버(결정 1)가 자리와 함께 쪽을 낸다. `SetEmojiCommand`가 로케이터와 `EmojiRig_Place`에 가로 배율을 넣는다 | 왼쪽을 보는 인물에게 맞는 쪽에 뜬다 |
| 2-D | 툴 — 이모지의 `side`와 리그의 `upright`를 고치는 칸, 내보내기, "왼쪽을 보는 인물로 보기" 미리보기. 툴의 계획서에 단계로 적는다 | 툴에서 양쪽을 다 본다 |
| 2-E | 견본 — `question`의 리그에 `upright`. 데모 대본에 뒤집힌 인물에게 띄우는 줄. 테스트(EditMode · 툴의 대조) | Unity에서 보인다 |

**하지 않는 것**: 화면의 어디에 섰는가로 쪽을 자동으로 고르는 것(가장자리 피하기) — 규칙이 눈에 안 보여 연출자가 결과를 예측하지 못한다.

## 4. 결정 3 — 같은 움직임에 다른 그림

**무엇이 남았나**: 툴의 스킨이 하던 일 넷 중 셋은 옮겼다(그림은 리그가, 놓임은 리그의 기본값이, 그림 넘기기는 계단 키가). 남은 하나가 "같은 움직임에 그림 묶음만 다른 것"이고, 그중 **반전 판은 결정 2가 푼다.** 그러면 남는 것은 색이나 그림만 다른 이모지(예: 하트 빨강 · 검정)다.

### 정할 것

| | 무엇 | 제안 | 까닭 · 다른 길 |
|---|---|---|---|
| 3-1 | 실제로 필요한가 | **소유자가 실례를 든다** — 지금 만들려는 이모지 목록에 "움직임은 같고 그림만 다른 것"이 몇 벌인가 | 한두 벌이면 길을 낼 까닭이 없다 |
| 3-2 | 어디서 묶는가 | **툴에서만** — 런타임과 형식은 그대로 둔다 | 런타임에게는 이름이 다른 이모지 둘일 뿐이다(`heart` · `heart_black`). [emoji-rig.md](emoji-rig.md) §2 "모션은 그 이모지의 것이다 · 한 덩어리로 나간다"가 그대로다. **다른 길**: 형식에 그림 묶음을 두고 대본이 고른다(`<<emoji s1 heart black>>`) — 대본의 셋째 칸을 좌우(2-5)와 다투고, 런타임이 합성을 하게 된다 |
| 3-3 | 툴에서 어떻게 | ① **지금**: "이모지 복제 + 그림 갈기"(복제한 뒤에는 서로 남이다). ② **같은 수정을 두 번 하게 되면**: 딸린 이모지 — 원본을 가리키고 그림 바꿈표만 들며, 내보낼 때 온전한 이모지로 펼친다 | ①은 정의의 "재사용은 가져와서 고치는 것"과 같다. ②는 몇 년 쓰는 동안 원본의 키를 고쳤을 때 색 판이 따라오게 한다 — 필요가 보일 때 만든다 |

### 작업 (정한 뒤)

- ①이면: 툴에 복제 명령이 이미 있는지 보고, 없으면 얹는다(툴의 계획서에 한 단계). 런타임의 일은 없다.
- ②이면: 툴의 모델(딸린 이모지 · 바꿈표) · 내보낼 때 펼치기 · 화면. 런타임의 일은 없다.

## 5. 일하는 법

- 앞 계획과 같다 — 결정마다 소유자가 "정할 것"을 닫고, 지시로 시작하고, 커밋은 소유자가 한다.
- 형식을 바꾸는 것은 결정 2뿐이다(`upright` · `side` — 더하는 칸). **런타임이 먼저 정하고(2-A · 2-B) 툴이 가져간다** — 코어 사본의 흐름은 한 방향이다.
- 결정 1은 런타임만 고친다. 툴은 결정 1 동안 건드리지 않는다.
- Unity가 있어야 보이는 것은 결정마다 "Unity 확인 목록"으로 넘긴다.
